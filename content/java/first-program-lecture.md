# Первая программа на Java

## Первая программа: сначала видим файл целиком

Для этого примера не нужны классы объектов Student, Scanner, циклы или ввод с клавиатуры. Сначала разберём минимальный работающий файл и научимся отличать его устройство от выбранного текста.

```java
public class HelloDemo {
    public static void main(String[] args) {
        System.out.println("Привет, Java!");
        System.out.println(2 + 3);
    }
}
```

Сохрани как HelloDemo.java. Ожидаемый вывод:

```text
Привет, Java!
5
```

## Общая форма и заменяемые места

Это шаблон, а не готовая программа:

```text
public class ИмяКласса {
    public static void main(String[] args) {
        инструкции;
    }
}
```

ИмяКласса выбираешь ты и используешь согласованно в файле и команде запуска. Вместо инструкций помещается конкретный код. В показанном способе запуска main сохраняет своё имя и подходящий заголовок. Это не название произвольного метода, которое можно заменить без изменения способа запуска.

## Каждая часть заголовка

| Фрагмент | Что он задаёт |
|---|---|
| `public class HelloDemo` | Публичный класс с выбранным именем HelloDemo |
| Первая `{` | Начало тела класса |
| `public` у main | Доступность этой формы точки входа |
| `static` | Запуск метода без предварительного создания экземпляра HelloDemo |
| `void` | Отсутствие результата-значения у метода |
| `main` | Имя принятой здесь точки входа |
| `String[]` | Тип массива строк для аргументов запуска |
| `args` | Имя параметра, а не команда чтения с клавиатуры |
| Внутренние `{ }` | Границы тела main |
| Последняя `}` | Конец класса |

Значения public и static будут возвращаться в следующих темах. Сейчас важно не путать границы блоков: строка вывода находится внутри main, а main — внутри класса. Отступы помогают увидеть вложенность, но Java определяет её скобками.

## Почему System.out.println не одно слово

System — готовый класс. out — его статическое поле, через которое получаем поток вывода. println — метод этого потока. Точки связывают обращения. В круглых скобках передаётся аргумент, то есть то, что нужно напечатать.

В `println("Привет, Java!")` аргумент — текст в двойных кавычках. Кавычки обозначают границы строкового значения и не входят в сам печатаемый текст. Точка с запятой завершает инструкцию, она не часть сообщения.

В `println(2 + 3)` сначала вычисляется выражение 2 + 3, потом готовое число передаётся выводу. Это не печать самих знаков «2 + 3». Чтобы вывести такие знаки, напиши `println("2 + 3")`.

Метод print не добавляет перевод строки, а println добавляет. Поэтому два последовательных print могут напечатать части одной строки.

## Порядок выполнения без скрытых прыжков

| Событие | Что появилось в консоли | Куда идём дальше |
|---|---|---|
| Старт main | Пока ничего | К первой инструкции внутри него |
| Первая println | Привет, Java! | На новую строку и ко второй инструкции |
| Вычисление 2 + 3 | Пока прежний вывод | Передать число 5 методу println |
| Вторая println | 5 | К завершению main |

Объявление класса само по себе не печатает его имя. Завершение main не означает появления дополнительной пустой карточки объекта.

## Компилируем и запускаем вручную

Из папки исходного файла выполни:

```text
javac -encoding UTF-8 HelloDemo.java
java HelloDemo
```

Первая команда проверяет исходник и при успехе создаёт байт-код. Отсутствие сообщения при успешной компиляции обычно нормально. Вторая запускает класс. Если javac сообщает об ошибке, сначала исправь её: нормальная новая версия ещё не получена.

После изменения исходника повтори компиляцию перед запуском. Иначе можно случайно запустить старый .class и решить, что Java «не видит» новую строку.

## Разбираем частые ошибки по причине

| Ошибка | Почему возникает | Что проверить |
|---|---|---|
| javac не найден | Не настроены инструменты или путь к ним | Установку JDK и терминал |
| Требуется файл с именем класса | Публичный класс и имя файла расходятся | HelloDemo.java ↔ HelloDemo |
| Не найден main | Заголовок или имя точки входа не подходит | Сравнить с целым рабочим примером |
| `';' expected` | Часто пропущен конец инструкции | Указанную и предыдущую строку |
| Незакрытая строка | Не хватает парной кавычки | Границы текста, обычные двойные кавычки вместо типографских |
| Вывод старый | Запущен старый результат компиляции | Повторную компиляцию нужного файла |

Точный текст сообщения зависит от JDK и среды. Причина важнее заученной английской формулировки.

## Как внести изменение и понять его

Сначала поменяй только текст приветствия. Затем поменяй 2 + 3 на 4 * 5. Потом добавь третью println. После каждого изменения заранее запиши ожидаемый вывод.

Переименуй собственный класс в MyFirstProgram, переименуй файл и измени команду запуска. Не переименовывай println в придуманное слово: это уже существующий метод библиотеки, а не твоя переменная.

## 1. Зачем это отдельная тема

Сейчас мы пишем код в **онлайн-компиляторе** — это нормально и достаточно для первых занятий: не нужно ничего ставить на компьютер, код пишется и запускается прямо в браузере. Но у этого есть обратная сторона: онлайн-компилятор скрывает от вас то, что на самом деле происходит при запуске программы, а без этого понимания структура кода (`public class`, `static`, `void`, `main`) выглядит как магическое заклинание, которое просто «надо писать, потому что так надо». Эта лекция закрывает именно этот пробел — а заодно готовит к переходу на Android Studio, о котором говорилось в [[0 Введение в курс|лекции 0]]: там всё то же самое, только компилятор встроен в среду разработки, а не находится на чужом сервере в интернете.

## 2. Что вообще нужно, чтобы Java заработала

У Java, в отличие от, например, Python, нет «одного шага» от текста программы до результата. Путь такой:

1. Вы пишете код в текстовом файле с расширением `.java` — это обычный текст, компьютер (и тем более процессор) его пока не понимает.
2. **Компилятор** `javac` (входит в JDK — Java Development Kit) переводит этот текст в **байт-код** — файл с расширением `.class`. Байт-код — это уже не текст и не машинный код процессора, а промежуточный формат, понятный не процессору напрямую, а специальной программе.
3. **Виртуальная машина Java** (JVM, Java Virtual Machine) запускает этот байт-код — уже она превращает его в реальные инструкции для процессора и печатает результат.

Схематически:

```
MyProgram.java  --(javac)-->  MyProgram.class  --(java, то есть JVM)-->  результат на экране
   (текст)                      (байт-код)
```

Именно из-за этого двойного шага (компиляция → выполнение) Java называют «компилируемым в байт-код» языком — не совсем как C++ (который компилируется сразу в код процессора) и не совсем как Python (который построчно выполняется интерпретатором без отдельного шага компиляции). Тот же самый байт-код, кстати, порождает и Kotlin после компиляции — поэтому в лекции 0 говорилось, что Java и Kotlin «работают на одной JVM»: `javac` там заменяется на компилятор Kotlin, но дальше всё то же самое.

**Что делает онлайн-компилятор.** Он выполняет оба шага (и `javac`, и `java`) за вас на своём сервере, а вам показывает только результат — то, что вывела программа. Когда позже вы поставите JDK и/или Android Studio на свой компьютер, вы будете делать ровно то же самое, просто явно (либо кнопкой «Run» в IDE, либо командами `javac` и `java` в терминале) и на своей машине, а не на чужой.

## 3. Анатомия простейшей программы — разбор каждого слова

Вот минимальная работающая Java-программа:

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Привет, мир!");
    }
}
```

Разберём буквально каждое слово — что оно значит и что будет, если его убрать или изменить.

- **`public`** (у класса) — модификатор доступа: класс виден отовсюду, в том числе снаружи файла. Без этого слова класс тоже скомпилируется, но не сможет быть точкой входа для запуска извне так же свободно — на первых порах просто всегда пишите `public` перед классом, который запускаете.
- **`class`** — ключевое слово: «дальше идёт описание класса». В Java **вообще весь код** обязан находиться внутри какого-нибудь класса — в отличие от Python, где `print("привет")` можно написать прямо в файле само по себе, в Java такой «код сам по себе» без класса компилятор не примет.
- **`HelloWorld`** — имя класса. Правило, которое ломает программу чаще всего у новичков: **имя файла обязано совпадать с именем public-класса**. Если класс называется `HelloWorld`, файл обязан называться `HelloWorld.java` — не `hello.java`, не `main.java`. Компилятор `javac` буквально ищет по имени файла, какой класс в нём главный.
- **`{` и `}`** (первая пара) — обозначают начало и конец тела класса: всё, что относится к классу `HelloWorld` (в данном случае — единственный метод `main`), находится между этими скобками.
- **`public static void main(String[] args)`** — это не четыре независимых слова, а единая, фиксированная **сигнатура точки входа**. JVM, запуская программу, ищет в классе метод, который выглядит ровно так — измените в этой строке хоть одно слово не по правилам, и программа перестанет запускаться (хотя может при этом успешно скомпилироваться). Разберём и здесь каждое слово:
  - **`public`** — метод должен быть виден снаружи класса, потому что JVM вызывает его как раз «снаружи», не будучи частью вашего класса.
  - **`static`** — ключевое слово, означающее «метод принадлежит самому классу, а не какому-то конкретному объекту». Это важно понять именно сейчас, до темы классов и объектов (лекция 1.2.1): обычно, чтобы вызвать метод объекта, сначала нужно создать сам объект (`new HelloWorld()`), а чтобы создать объект — нужна уже работающая программа, которая это сделает. Получается замкнутый круг: чтобы начать программу, нужен уже работающий метод, но чтобы вызвать обычный метод — нужен объект. `static` разрывает этот круг: `main` привязан к классу целиком, и JVM может вызвать его безо всякого объекта, с самого начала, с чистого листа.
  - **`void`** — метод `main` ничего не **возвращает** обратно тому, кто его вызвал (в данном случае — самой JVM). Здесь нет `return значение;`, и это осознанное решение: программа сообщает о своём результате не через возвращаемое значение метода, а через побочные эффекты — печать на экран, запись в файл, изменение данных на сервере и так далее.
  - **`main`** — не ключевое слово, а строго зафиксированное **имя** метода, которое ищет JVM. Назовите его `Main` (с большой буквы) или `mian` (опечатка) — и JVM скажет: «метод main не найден», хотя код скомпилируется без единой ошибки, ведь с точки зрения синтаксиса Java это просто обычный метод с необычным именем.
  - **`(String[] args)`** — параметр метода: массив строк. Через него в программу попадают **аргументы командной строки** — то, что можно передать программе при запуске (`java HelloWorld один два три`, тогда `args = {"один", "два", "три"}`). Если ничего не передать (как чаще всего и происходит в онлайн-компиляторе), `args` — это просто пустой массив, не `null`, а именно массив длины `0`. Даже если вы им никогда не пользуетесь, писать этот параметр всё равно обязательно — того требует сигнатура точки входа.
- **`System.out.println("Привет, мир!");`** — единственная содержательная строка. Разбор по частям:
  - **`System`** — встроенный класс Java, представляющий саму систему (компьютер, на котором выполняется программа): доступ к консоли, часам, переменным окружения.
  - **`.out`** — статическое поле класса `System`, представляющее поток стандартного вывода (то есть «консоль» / «экран»); тип этого поля — `PrintStream`.
  - **`.println(...)`** — метод объекта `System.out`, который печатает переданное значение и переводит строку (`ln` — сокращение от *line*). Есть и `.print(...)` — то же самое, но без перевода строки в конце: следующий вывод продолжится на той же строке.
  - **`"Привет, мир!"`** — строковый литерал (тип `String`), заключённый в двойные кавычки — то, что будет напечатано.
  - **`;`** — точка с запятой, обязательный конец каждой инструкции в Java. Забытая точка с запятой — вторая по частоте причина ошибок компиляции у новичков (первая — незакрытая или лишняя фигурная скобка).

## 4. Типичные ошибки при первом запуске

Все эти ошибки в онлайн-компиляторе выглядят как «красный текст» с сообщением — вот как их читать:

| Что написали | Что говорит компилятор/JVM | В чём дело |
|---|---|---|
| `class HelloWorld` без `public`, а файл называется иначе | Компилируется, но не запускается как ожидалось | Некоторые онлайн-компиляторы жёстко требуют, чтобы класс назывался именно `Main` — если ошибка про «имя класса», переименуйте класс в `Main` |
| `public static void Main(...)` (с большой буквы) | `Error: Main method not found in class ...` | Java чувствительна к регистру: `Main` ≠ `main` |
| Забыта `;` после `System.out.println(...)` | `error: ';' expected` | Каждая инструкция обязана заканчиваться `;` |
| Не закрыта фигурная скобка `{` | `error: reached end of file while parsing` | Компилятор досчитал до конца файла, а пары скобке так и не нашёл — считайте открывающие и закрывающие скобки парами |
| `System.out.Println(...)` (с большой буквы) | `cannot find symbol` | Имена методов тоже чувствительны к регистру — правильно `println`, не `Println` |

## 5. Дополнительный разбор после темы типов: лабораторная работа 1

Лабораторная работа 1 (та, что осталась с прошлого года) состоит из пяти маленьких программ. Разберём первую и вторую полностью — по тому же принципу дальше читаются и остальные три.

### Программа 1 — явное и неявное преобразование

```java
public class FloatConversion {
    public static void main(String[] args) {
        double doubleValue = 10.5;
        int intValue = (int) doubleValue; // явное преобразование

        System.out.println("Явное преобразование: " + intValue);

        float floatValue = 15.75f;
        double doubleVal = floatValue; // неявное преобразование

        System.out.println("Неявное преобразование: " + doubleVal);
    }
}
```

- `public class FloatConversion` — файл обязан называться `FloatConversion.java` (см. раздел 3 выше).
- `double doubleValue = 10.5;` — объявление переменной типа `double` (число с плавающей точкой двойной точности) и сразу присваивание значения. Слева от `=` — тип и имя, справа — значение; это одна инструкция, поэтому в конце `;`.
- `int intValue = (int) doubleValue;` — здесь `(int)` перед `doubleValue` — это **явное приведение типа** (cast): вы прямо говорите компилятору «преврати double в int, даже если при этом что-то потеряется». Потеряется дробная часть: `10.5` станет `10` (округления в большую сторону не будет — дробная часть просто отбрасывается, это называется усечением). Явное приведение нужно именно потому, что такое преобразование **сужающее** — из типа, который вмещает больше информации (`double`), в тип, который вмещает меньше (`int`), — и Java не станет делать это молча, заставит написать `(int)` явно, чтобы вы точно понимали, что теряете точность.
- `// явное преобразование` — однострочный комментарий: всё после `//` до конца строки компилятор игнорирует, это заметка для человека, читающего код.
- `System.out.println("Явное преобразование: " + intValue);` — здесь знак `+` работает не как арифметическое сложение, а как **конкатенация строк**: раз слева от `+` стоит `String` (`"Явное преобразование: "`), Java автоматически превращает `intValue` (число) в его текстовое представление и склеивает строки. Это отдельное, важное правило: `+` между строкой и числом всегда означает склейку, а не сложение — частая путаница у тех, кто уже писал на языках, где это работает иначе.
- `float floatValue = 15.75f;` — буква `f` в конце числового литерала обязательна для типа `float`: без неё `15.75` компилятор по умолчанию считает `double`, и присвоить `double`-литерал переменной типа `float` напрямую нельзя (это тоже сужающее преобразование — `float` занимает меньше памяти и не хранит всю точность `double`).
- `double doubleVal = floatValue;` — а вот здесь приведения `(double)` не нужно: `float` → `double` — это **расширяющее** преобразование (из типа с меньшим диапазоном в тип с большим), Java выполняет его автоматически и молча, потому что при расширении ничего не теряется.

### Программа 2 — преобразование между числом и строкой

```java
public class TypeConversion {
    public static void main(String[] args) {
        int intValue = 10;
        String strValue = String.valueOf(intValue);

        System.out.println("Целочисленный тип в строковый тип: " + strValue);

        String str = "25";
        int intVal = Integer.parseInt(str);

        System.out.println("Строковый тип в целочисленный тип: " + intVal);
    }
}
```

- `String strValue = String.valueOf(intValue);` — `String.valueOf(...)` — статический метод класса `String` (обратите внимание: вызывается через имя класса `String`, а не через объект, — это тоже `static`, как и `main`), превращающий число в его текстовое представление. Это **не** то же самое, что приведение типа `(String) intValue` — так вообще написать нельзя, приведение типов работает только между «родственными» типами (числовыми между собой, например), а превращение числа в текст — это не приведение типа, а настоящее преобразование данных, поэтому и нужен отдельный метод.
- `int intVal = Integer.parseInt(str);` — обратная операция: `Integer` — класс-обёртка над примитивным типом `int` (о таких классах будет отдельный разговор в теме про ссылочные типы), его статический метод `parseInt` разбирает строку и возвращает `int`. Важно: если строка не является корректным числом (например, `"двадцать пять"` или `"25a"`), эта строка выбросит ошибку времени выполнения (`NumberFormatException`) — программа скомпилируется без проблем, но упадёт именно в момент выполнения этой строки. Про обработку таких ошибок (`try`/`catch`) будет отдельная тема позже, пока просто держите в голове: `parseInt` — операция, которая может не сработать, если строка «не похожа» на число.

### Программы 3–4 — то же самое, но с логикой, которую вы уже разбирали в лекции 1

`LogicalOperations` и `ComparisonOperations` не вводят ничего нового по структуре — это тот же самый скелет `public class ... { public static void main(String[] args) { ... } }`, а внутри — операции `&&`, `||`, `!`, `>`, `<`, `==`, которые уже разобраны в [[1 Типы данных и операции|лекции 1]]. Если структура (класс, `main`, `System.out.println`) теперь понятна, эти две программы читаются свободно — тренируйтесь читать их самостоятельно, сверяя с разделом 3 этой лекции при любом непонятном слове.

## 6. Итог лекции

Структура `public class Имя { public static void main(String[] args) { ... } }` — не набор слов «для галочки», а точная формула, где у каждого слова есть причина: `public class` — единица кода, которую видит JVM снаружи; `static` — разрывает круг «нужен объект, чтобы вызвать метод, но нужен метод, чтобы создать первый объект»; `void` — программа сообщает результат не через `return`, а через побочные эффекты вроде печати на экран; `String[] args` — канал для аргументов командной строки, даже когда он не используется. Путь от текста программы до результата на экране всегда проходит два шага — компиляцию (`javac`, текст → байт-код) и выполнение (`java`/JVM, байт-код → результат), просто в онлайн-компиляторе оба шага скрыты под одной кнопкой «Run». Когда в лекции 0 речь пойдёт про установку Android Studio — это будет ровно тот же процесс, просто явный и локальный, а не спрятанный на чужом сервере.

**Проверь себя:**

1. Почему метод `main` обязан быть `static`, а не обычным методом объекта? Что произошло бы, если бы JVM пришлось сначала создать объект класса, чтобы вызвать его метод?
2. В программе `FloatConversion` строка `int intValue = (int) doubleValue;` требует явного приведения типа `(int)`, а строка `double doubleVal = floatValue;` — нет. В чём разница между этими двумя преобразованиями и почему Java требует явности только в одном случае?
3. Вы написали класс `public class Solution` в файле с именем `main.java`. Что произойдёт при попытке скомпилировать этот код и как это исправить?
4. Чем отличается результат выражения `"Результат: " + 5 + 3` от `"Результат: " + (5 + 3)`? Объясните, почему они дают разный вывод, опираясь на то, как работает `+` со строками.
5. `Integer.parseInt("25a")` не сработает и «уронит» программу в момент выполнения, хотя код с этой строкой компилируется без единой ошибки. Почему компилятор не может обнаружить эту проблему заранее, на этапе `javac`?
