# 1.2.2 Конструкторы

## Основные понятия



> **Конструктор** — специальное объявление класса, задающее действия при инициализации нового экземпляра. Его имя совпадает с именем класса, тип результата не пишется.

>

> **Перегрузка конструкторов** — несколько конструкторов одного класса с разными списками параметров.

>

> **`this.field`** — обращение к полю текущего объекта; **`this(...)`** — вызов другого конструктора того же класса.

>

> **Конструктор по умолчанию** предоставляется компилятором, если в обычном классе не объявлен ни один конструктор.

>

> **`private`** ограничивает прямой доступ к члену класса; в наших отдельных учебных классах обращаться к закрытому полю можно из кода его собственного класса.

>

> **Геттер** возвращает значение свойства. **Сеттер** предлагает изменить свойство; необходимость сеттера и проверки определяются правилами класса.



## 1. Проблема незаполненной карточки

«Выдали пропуск, но забыли написать имя. Формально карточка есть, пользоваться ей неудобно. В программе произошло то же: объект создали, а одну из строк заполнения забыли. Пусть данные передаются сразу на вход при создании».

```java
Student anna = new Student("Анна", 70);
```

Имя и энергия — аргументы. Конструктор получает их в параметрах, проверяет и сохраняет в полях. Это не метод с типом результата `Student`: перед именем конструктора не пишется ни `Student`, ни `void`.

## 2. Разбираем конструктор по словам

```java
Student(String name, int energy) {
    this.name = name;
    this.energy = energy;
}
```

Слева от `=` поле конкретного объекта, справа параметр текущего вызова. Оба могут называться `name`, но это разные переменные.

Внешняя карточка объекта: поле `name = null`. Рядом карточка вызова: параметр `name = "Анна"`. Стрелка присваивания идёт от параметра к полю. `this` отвечает на вопрос «чьё поле?» — создаваемого объекта.

Если написать `name = name`, параметр присвоится самому себе. Поле останется со своим прежним значением, например `null`. Программа может скомпилироваться, поэтому отсутствие красного подчёркивания не доказывает правильность.

## 3. Порядок создания без лишней магии

Для нашего простого класса без наследования и инициализаторов: выделяется память объекта, поля получают значения по умолчанию, выполняется необходимая инициализация и тело конструктора. При нормальном завершении выражение `new` даёт ссылку, которую можно сохранить в `anna`.

Если проверка в конструкторе выбросила исключение, выражение `new` не завершилось обычным возвратом готовой ссылки и присваивание `anna` не выполняется. Конструктор не является обычной фабрикой, которой мы вручную пишем `return this`.

«Можно ли вызвать конструктор на старом объекте, чтобы заново его заполнить?» Не как обычный метод `anna.Student(...)`. Для изменения состояния используем методы, а новое `new Student(...)` создаёт другой экземпляр.

## 4. Почему исчез new Student()

Когда конструкторов в исходнике не было, компилятор предоставлял конструктор по умолчанию. Когда написали хотя бы один собственный, такой конструктор уже не добавляется автоматически.

Если объявлен только `Student(String name, int energy)`, вызов `new Student()` не подходит. Решения: передать нужные аргументы или сознательно написать ещё один конструктор. Нельзя «лечить» ошибку добавлением `void`: это превратит объявление в обычный метод с именем класса.

## 5. Два удобных способа создать один и тот же тип

```java
Student(String name) {
    this(name, 100);
}
```

Один аргумент означает: имя задано, энергия по умолчанию 100. Этот конструктор вызывает основной, где сосредоточены проверки и присваивания. В результате одного `new Student("Борис")` создаётся один объект, а не два: цепочка конструкторов инициализирует тот же экземпляр.

В примерах этого курса пиши `this(...)` первой инструкцией. Такой стиль совместим с Java 17/21. Это не универсальное ограничение всех версий языка: начиная с Java 25 допускаются некоторые инструкции до явного вызова конструктора при специальных ограничениях. Для текущих задач достаточно простой формы, показанной здесь.

## 6. Проверка должна защищать и создание, и изменение

Энергия допустима от 0 до 100. В старом варианте сеттер мог напечатать ошибку и выйти; при вызове из конструктора объект всё равно создавался с полем 0. Это скрывает отказ. Здесь выберем явное поведение: недопустимое значение вызывает `IllegalArgumentException`.

```java
if (energy < 0 || energy > 100) {
    throw new IllegalArgumentException("Энергия должна быть от 0 до 100");
}
```

«`throw` означает: продолжать как будто всё удалось нельзя. Мы сообщаем об ошибке входных данных. Это не возвращённое число и не обычная надпись в консоли». Полный курс исключений позже; сегодня достаточно видеть, что после неверных данных создание нормально не завершится.

В итоговом классе проверка вынесена в закрытый static-метод `checkEnergy`: ему требуется только переданное число, а не состояние конкретного студента. Конструктор и сеттер вызывают одну проверку, поэтому тебе не нужно поддерживать два одинаковых условия. Смысл static подробнее разобран в следующей теме.

Конструктор не вызывает переопределяемый публичный сеттер. Это избавляет от ненужной зависимости создания от поведения, которое позже может измениться в наследнике.

## 7. Закрытые поля и разумный интерфейс

В итоговом классе поля `private`. Попытка `anna.energy = -5` из другого класса не скомпилируется. При этом `getEnergy()` возвращает текущее значение, а `setEnergy(...)` проверяет новое перед присваиванием. При отказе старое значение остаётся прежним.

У имени есть геттер, но нет сеттера: для этого учебного сценария переименование не предусмотрено. Это проектное решение, а не правило, что имена никогда не меняются. Отсутствие сеттера означает «через этот интерфейс изменение не предлагается», а не автоматически делает весь объект неизменяемым.

Геттер и сеттер — обычные методы. Их названия облегчают чтение. Не создавать их бездумно для всех полей: например, у банковского счёта безопаснее операции пополнения и списания, чем произвольная установка баланса.

## 8. Как программа сообщает об отказе

В примере `try` охватывает вызов, который может завершиться ошибкой, а `catch (IllegalArgumentException error)` получает именно такую ошибку и позволяет вывести сообщение. Сначала запусти создание с допустимой энергией, затем передай неверное значение. В первом случае появляется готовая ссылка, а во втором управление переходит в catch. Проследи эти два пути; остальные возможности исключений ты изучишь отдельно.

Проверь значения 0, 100, −1 и 101. Первые два должны приниматься, последние два — отклоняться. Пограничные значения важнее десяти случайных запусков.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 ConstructorsDemo.java`, затем `java ConstructorsDemo`. JDK 17 или новее.

```java
public class ConstructorsDemo {
    public static void main(String[] args) {
        Student anna = new Student("Анна", 70);
        Student boris = new Student("Борис");
        System.out.println(anna.getName() + ": " + anna.getEnergy());
        System.out.println(boris.getEnergy());
        try {
            anna.setEnergy(150);
        } catch (IllegalArgumentException error) {
            System.out.println("Изменение отклонено");
        }
        System.out.println(anna.getEnergy());
        try {
            new Student("Ошибка", -1);
        } catch (IllegalArgumentException error) {
            System.out.println("Создание отклонено");
        }
    }
}
class Student {
    private String name;
    private int energy;
    Student(String name, int energy) {
        checkEnergy(energy);
        this.name = name;
        this.energy = energy;
    }
    Student(String name) {
        this(name, 100);
    }
    public String getName() {
        return name;
    }
    public int getEnergy() {
        return energy;
    }
    public void setEnergy(int energy) {
        checkEnergy(energy);
        this.energy = energy;
    }
    private static void checkEnergy(int energy) {
        if (energy < 0 || energy > 100) {
            throw new IllegalArgumentException("Энергия должна быть от 0 до 100");
        }
    }
}
```

Ожидаемый вывод:

```text
Анна: 70
100
Изменение отклонено
70
Создание отклонено
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.
