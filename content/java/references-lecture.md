# Ссылки

## Начни с одного правила: присваивание копирует значение

Для int значением является число. Для ссылочной переменной — ссылка на объект либо null. Поэтому один и тот же знак `=` может копировать число или ссылку. Объект за ссылкой от одного такого присваивания не клонируется.

Представь две записки с маршрутом к одной комнате. Сделали вторую записку — комнаты не стало две. Переставили мебель в комнате — человек с любой запиской увидит изменения. Переписали только одну записку на другую комнату — другая записка осталась прежней.

Это аналогия доступа, а не обещание настоящего числового адреса в Java. У ссылок нет доступной обычному коду арифметики «прибавить один и попасть в соседнюю ячейку».

## Общая форма

```text
СсылочныйТип первоеИмя = выражениеСозданияОбъекта;
СсылочныйТип второеИмя = первоеИмя;
второеИмя = другаяСсылка;
```

СсылочныйТип может быть int[], String или твоим классом. Имена выбираешь ты. Вторая строка копирует значение ссылки, а третья переназначает только указанную переменную. Чтобы изменить элемент массива, нужна другая левая часть: `имяМассива[индекс]`.

## Полный опыт с числами, массивом и переназначением

```java
public class ReferenceReviewDemo {
    public static void main(String[] args) {
        int number = 5;
        int numberCopy = number;
        numberCopy = 9;
        int[] first = {5, 7};
        int[] second = first;
        second[0] = 9;
        System.out.println(number);
        System.out.println(first[0]);
        second = new int[]{1, 2};
        System.out.println(first[0]);
        System.out.println(second[0]);
    }
}
```

Файл ReferenceReviewDemo.java. Вывод: **5, 9, 9, 1**, каждое число с новой строки.

## Каждая строка меняет определённую вещь

`numberCopy = 9` записывает новое число только в numberCopy. `second[0] = 9` идёт по ссылке second и меняет **элемент общего массива**. `second = new int[]{1, 2}` меняет уже саму переменную second и создаёт отдельный массив.

| Этап | first | second | Число массивов, созданных нашим кодом |
|---|---|---|---:|
| Создали first | Ссылка на А: [5, 7] | Ещё нет | 1 |
| second = first | Ссылка на А | Та же ссылка на А | 1 |
| second[0] = 9 | А теперь [9, 7] | Тот же А | 1 |
| second = new ... | Прежний А: [9, 7] | Б: [1, 2] | 2 |

Имя А — условная метка на схеме, не адрес, который нужно искать в выводе программы.

## Что именно получает параметр метода

При `change(first)` параметр получает **копию значения ссылки**. Если метод пишет в элемент общего массива, изменение видно вызывающему коду. Если он присваивает параметру ссылку на другой массив, меняется только локальная переменная-параметр.

Это не два разных режима передачи. Java всегда передаёт аргументы по значению. Чтобы заменить переменную вызывающего кода новым массивом, можно вернуть ссылку методом и явно присвоить результат снаружи.

## null, пустой массив и строка — не одно и то же

`int[] values = null` — объекта массива за этой переменной нет. `new int[0]` — объект существует, просто элементов ноль. `String text = ""` — существует пустая строка, а не null.

Поэтому значения нельзя подменять друг другом без изменения смысла. Длина пустого массива доступна и равна 0. Чтение длины через null приводит к ошибке. В массиве String[3] сам массив есть, но его элементы первоначально null.

## Сравнить один объект или одинаковое содержимое

Для ссылок `==` проверяет, ведут ли они к одному объекту, либо обе равны null. У String метод equals сравнивает текст. У нового собственного класса без переопределения equals не появляется автоматическое сравнение всех полей. У массива его обычный equals тоже не сравнивает элементы.

Совпадающие литералы строк могут разделять один объект. Поэтому успешно сработавший `==` на двух одинаковых литералах не доказывает, что так правильно сравнивать произвольный текст.

String неизменяем: операция соединения текста не переписывает символы старого объекта. Но строковую переменную можно переназначить другому строковому значению.

## Как перейти к собственной проверке

Сначала используй массив из двух целых. Нарисуй отдельно переменные и массивы. После каждой строки меняй **либо содержимое объекта, либо стрелку**. Затем добавь clone для int[] и предскажи, какие изменения станут независимыми.

Не делай из clone обещание полного копирования дерева объектов: у массива ссылок копируются элементы-ссылки, а связанные объекты могут остаться общими.

Проверь себя: что станет с first, если second присвоить null после копирования ссылки? first сохранит прежнюю ссылку. null в одной переменной не является командой немедленно уничтожить общий объект.

## Справочник и дополнительные упражнения по теме

## Основные понятия



> **Ссылка** — значение, с помощью которого Java обращается к объекту. Ссылочная переменная хранит ссылку на объект или `null`.

>

> **Присваивание** копирует значение правой части в переменную слева. Копирование ссылки само по себе не создаёт копию объекта.

>

> **`null`** — специальное значение, означающее отсутствие ссылки на объект.

>

> **В Java аргументы передаются по значению:** метод получает копию значения аргумента. Для ссылочного типа копируется значение ссылки.

>

> **Строка `String` неизменяема:** содержимое существующего строкового объекта изменить нельзя.



## 1. Две записки к одному шкафчику

«У вас есть школьный шкафчик с вещами. На двух записках написано, как найти один и тот же шкафчик. Сделали вторую записку — вещей больше не стало. Изменили вещи через одну записку — человек с другой увидит изменения. Но если переписать одну записку на другой шкафчик, первая записка не изменится».

У аналогии есть граница: Java-ссылка не является доступным программисту числовым адресом. Нельзя прибавить к ссылке единицу и перейти к «соседней ячейке». На схемах используем условные объекты А и Б, а не настоящие адреса.

![[Схемы ООП/01 Ссылки.png]]

Нарисуй переменную first и массив, к которому ведёт её стрелка. После `second = first` добавь только вторую переменную и стрелку к прежнему массиву. После `second[0] = 99` измени клетку массива, а не стрелку. Так ты увидишь разницу между копированием ссылки и изменением объекта.

```java
int[] first = {10, 20};
int[] second = first;
second[0] = 99;
System.out.println(first[0]);
```

Ответ — 99. Прочитать последовательно: создали массив; скопировали ссылку; нашли общий массив через `second`; поменяли элемент; прочитали его через `first`.

«Сколько объектов-массивов создано?» Один. «Сколько ссылочных переменных?» Две. «Почему не два массива?» Вторая строка не создаёт объект, она присваивает существующее значение ссылки.

## 2. Изменить объект и переназначить переменную — разные действия

```java
second = new int[]{7, 8};
System.out.println(first[0]);
System.out.println(second[0]);
```

Теперь результаты 99 и 7. `second` получила ссылку на другой массив. Старый массив по-прежнему доступен через `first`. В строке `second[0] = ...` слева элемент объекта; в строке `second = ...` слева сама переменная. Обведи эти разные левые части.

Два человека могут редактировать один список. Если тебе нужен независимый список, одного присваивания мало. Для массива `int[]` можно использовать `first.clone()`: получится отдельный массив со скопированными числами. Для массива ссылок такая копия была бы поверхностной: копируются ссылки в ячейках, а объекты за ними могут остаться общими. clone не означает полную независимую копию всего.

## 3. Числа ведут себя иначе, потому что копируется другое значение

```java
int firstScore = 10;
int secondScore = firstScore;
secondScore = 99;
System.out.println(firstScore);
```

Ответ — 10. Правило присваивания то же. Различается значение: здесь копировалось число, в предыдущем примере — ссылка. Неверно думать, что знак `=` для объектов «вдруг работает иначе».

## 4. Почему метод меняет массив, но не заменяет переменную вызывающего кода

В полном примере внизу есть два метода. `changeFirst(values)` выполняет `values[0] = 42`. Параметр и переменная `main` ведут к одному массиву, поэтому изменение видно снаружи.

`replace(values)` выполняет `values = new int[]{100, 200}`. Меняется только локальный параметр метода. Переменная `main` остаётся со своей прежней ссылкой.

Добавь к своей схеме отдельную переменную-параметр `метод: values` рядом с `main: numbers`. Сначала обе стрелки ведут к А. При переназначении измени стрелку только у values, направив её к Б. У numbers стрелка к А остаётся: это другая переменная.

«Массив передали по ссылке?» Точная формулировка: передали значение ссылки по значению. Объект общий, переменные разные. Чтобы вернуть новый массив вызывающему коду, метод может сделать `return`, а вызывающий код — присвоить результат.

## 5. `null`: записка без маршрута

```java
int[] missing = null;
if (missing != null) {
    System.out.println(missing.length);
}
```

Массива здесь нет. Это не массив длиной ноль: у `new int[0]` объект есть и длина равна нулю. Попытка прочитать `missing.length` без проверки приведёт к `NullPointerException`. Проверка нужна **до** обращения.

Массив `String[] names = new String[3]` существует, но каждый из трёх элементов сначала равен `null`. Поэтому `names.length` работает, а `names[0].length()` пока нет. Нельзя путать существование контейнера и существование объектов в его ячейках.

## 6. Строки: переменная меняется, текст старого объекта — нет

```java
String firstText = "Кот";
String secondText = firstText;
firstText = firstText + "!";
System.out.println(secondText);
```

Результат — «Кот». Выражение получает строковое значение «Кот!», а переменная `firstText` переназначается. `secondText` продолжает ссылаться на прежнюю строку. Это не означает, что переменную типа `String` запрещено менять.

Для ссылок `==` проверяет, один ли это объект, либо обе ссылки `null`. Для текста у `String` используем `equals`: `"Кот".equals(secondText)`. Нельзя обобщать до «любой equals сравнивает содержимое»: класс сам определяет его поведение; у обычного нового класса без переопределения равенство остаётся по идентичности. У массивов `equals` также не сравнивает элементы; для них есть `Arrays.equals`.

Литералы строк могут разделять объект из пула, поэтому случайно работающий `==` для одинаковых литералов — плохое доказательство правильности сравнения текста.

## 7. Немного о памяти без мифа о двух коробках

Для урока достаточно модели «переменные и объекты со стрелками». У JVM есть стек вызовов и куча объектов, но память программы не сводится только к ним. Ссылки могут храниться и в полях объектов, и в элементах массивов; правило «все ссылки в стеке» неверно. Оптимизации JVM тоже не нужно выдавать за устройство каждой картинки.

Когда объект больше недостижим из работающей программы, сборщик мусора может освободить занятую им память. `variable = null` не команда немедленного уничтожения объекта: к нему могут оставаться другие пути. Не обещаем момент сборки и не используем `System.gc()` как учебный способ удаления.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 ReferencesDemo.java`, затем `java ReferencesDemo`. JDK 17 или новее.

```java
public class ReferencesDemo {
    public static void main(String[] args) {
        int[] first = {10, 20};
        int[] second = first;
        second[0] = 99;
        System.out.println(first[0]);
        second = new int[]{7, 8};
        System.out.println(first[0]);
        System.out.println(second[0]);
        changeFirst(first);
        replace(first);
        System.out.println(first[0]);
        String firstText = "Кот";
        String secondText = firstText;
        firstText = firstText + "!";
        System.out.println(secondText);
        System.out.println("Кот".equals(secondText));
    }
    static void changeFirst(int[] values) {
        values[0] = 42;
    }
    static void replace(int[] values) {
        values = new int[]{100, 200};
    }
}
```

Ожидаемый вывод:

```text
99
99
7
42
Кот
true
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.
