# 1.1.7 Ссылки

## Основные понятия



> **Ссылка** — значение, с помощью которого Java обращается к объекту. Ссылочная переменная хранит ссылку на объект или `null`.

>

> **Присваивание** копирует значение правой части в переменную слева. Копирование ссылки само по себе не создаёт копию объекта.

>

> **`null`** — специальное значение, означающее отсутствие ссылки на объект.

>

> **В Java аргументы передаются по значению:** метод получает копию значения аргумента. Для ссылочного типа копируется значение ссылки.

>

> **Строка `String` неизменяема:** содержимое существующего строкового объекта изменить нельзя.



## 1. Две записки к одному шкафчику

«У вас есть школьный шкафчик с вещами. На двух записках написано, как найти один и тот же шкафчик. Сделали вторую записку — вещей больше не стало. Изменили вещи через одну записку — человек с другой увидит изменения. Но если переписать одну записку на другой шкафчик, первая записка не изменится».

У аналогии есть граница: Java-ссылка не является доступным программисту числовым адресом. Нельзя прибавить к ссылке единицу и перейти к «соседней ячейке». На схемах используем условные объекты А и Б, а не настоящие адреса.

![[Схемы ООП/01 Ссылки.png]]

Сначала одна коробка `first` и один массив. После `second = first` добавляем только коробку и стрелку. После `second[0] = 99` меняем клетку массива, а не стрелку.

```java
int[] first = {10, 20};
int[] second = first;
second[0] = 99;
System.out.println(first[0]);
```

Ответ — 99. Прочитать последовательно: создали массив; скопировали ссылку; нашли общий массив через `second`; поменяли элемент; прочитали его через `first`.

«Сколько объектов-массивов создано?» Один. «Сколько ссылочных переменных?» Две. «Почему не два массива?» Вторая строка не создаёт объект, она присваивает существующее значение ссылки.

## 2. Изменить объект и переназначить переменную — разные действия

```java
second = new int[]{7, 8};
System.out.println(first[0]);
System.out.println(second[0]);
```

Теперь результаты 99 и 7. `second` получила ссылку на другой массив. Старый массив по-прежнему доступен через `first`. В строке `second[0] = ...` слева элемент объекта; в строке `second = ...` слева сама переменная. Обведи эти разные левые части.

В группе два человека могут редактировать один список. Если ожидается независимый список, одного присваивания мало. Для массива `int[]` можно использовать `first.clone()`: получится отдельный массив со скопированными числами. Для массива ссылок такая копия была бы поверхностной — это отдельная тема, не обещаем «полное клонирование всего».

## 3. Числа ведут себя иначе, потому что копируется другое значение

```java
int firstScore = 10;
int secondScore = firstScore;
secondScore = 99;
System.out.println(firstScore);
```

Ответ — 10. Правило присваивания то же. Различается значение: здесь копировалось число, в предыдущем примере — ссылка. Неверно думать, что знак `=` для объектов «вдруг работает иначе».

## 4. Почему метод меняет массив, но не заменяет переменную вызывающего кода

В полном примере внизу есть два метода. `changeFirst(values)` выполняет `values[0] = 42`. Параметр и переменная `main` ведут к одному массиву, поэтому изменение видно снаружи.

`replace(values)` выполняет `values = new int[]{100, 200}`. Меняется только локальный параметр метода. Переменная `main` остаётся со своей прежней ссылкой.

Рядом с коробкой `main: numbers` рисуем новую коробку `метод: values`. Сначала обе стрелки ведут к А. При переназначении стираем стрелку только у `values` и ведём к Б. У `numbers` стрелка к А остаётся.

«Массив передали по ссылке?» Точная формулировка: передали значение ссылки по значению. Объект общий, переменные разные. Чтобы вернуть новый массив вызывающему коду, метод может сделать `return`, а вызывающий код — присвоить результат.

## 5. `null`: записка без маршрута

```java
int[] missing = null;
if (missing != null) {
    System.out.println(missing.length);
}
```

Массива здесь нет. Это не массив длиной ноль: у `new int[0]` объект есть и длина равна нулю. Попытка прочитать `missing.length` без проверки приведёт к `NullPointerException`. Проверка нужна **до** обращения.

Массив `String[] names = new String[3]` существует, но каждый из трёх элементов сначала равен `null`. Поэтому `names.length` работает, а `names[0].length()` пока нет. Нельзя путать существование контейнера и существование объектов в его ячейках.

## 6. Строки: переменная меняется, текст старого объекта — нет

```java
String firstText = "Кот";
String secondText = firstText;
firstText = firstText + "!";
System.out.println(secondText);
```

Результат — «Кот». Выражение получает строковое значение «Кот!», а переменная `firstText` переназначается. `secondText` продолжает ссылаться на прежнюю строку. Это не означает, что переменную типа `String` запрещено менять.

Для ссылок `==` проверяет, один ли это объект, либо обе ссылки `null`. Для текста у `String` используем `equals`: `"Кот".equals(secondText)`. Нельзя обобщать до «любой equals сравнивает содержимое»: класс сам определяет его поведение; у обычного нового класса без переопределения равенство остаётся по идентичности. У массивов `equals` также не сравнивает элементы; для них есть `Arrays.equals`.

Литералы строк могут разделять объект из пула, поэтому случайно работающий `==` для одинаковых литералов — плохое доказательство правильности сравнения текста.

## 7. Немного о памяти без мифа о двух коробках

Для урока достаточно модели «переменные и объекты со стрелками». У JVM есть стек вызовов и куча объектов, но память программы не сводится только к ним. Ссылки могут храниться и в полях объектов, и в элементах массивов; правило «все ссылки в стеке» неверно. Оптимизации JVM тоже не нужно выдавать за устройство каждой картинки.

Когда объект больше недостижим из работающей программы, сборщик мусора может освободить занятую им память. `variable = null` не команда немедленного уничтожения объекта: к нему могут оставаться другие пути. Не обещаем момент сборки и не используем `System.gc()` как учебный способ удаления.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 ReferencesDemo.java`, затем `java ReferencesDemo`. JDK 17 или новее.

```java
public class ReferencesDemo {
    public static void main(String[] args) {
        int[] first = {10, 20};
        int[] second = first;
        second[0] = 99;
        System.out.println(first[0]);
        second = new int[]{7, 8};
        System.out.println(first[0]);
        System.out.println(second[0]);
        changeFirst(first);
        replace(first);
        System.out.println(first[0]);
        String firstText = "Кот";
        String secondText = firstText;
        firstText = firstText + "!";
        System.out.println(secondText);
        System.out.println("Кот".equals(secondText));
    }
    static void changeFirst(int[] values) {
        values[0] = 42;
    }
    static void replace(int[] values) {
        values = new int[]{100, 200};
    }
}
```

Ожидаемый вывод:

```text
99
99
7
42
Кот
true
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.
