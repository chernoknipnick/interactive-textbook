# Основы ООП — заключение под запись

**ООП** — организация решения через объекты с состоянием и доступными действиями. Главный вопрос: какой объект получает действие и что в нём меняется?

## Из чего складывается модель

| Понятие | Назначение |
|---|---|
| **Класс** | Описание экземпляров и действий |
| **Объект**, **экземпляр** | Конкретный созданный экземпляр класса |
| **Поле** | Переменная класса; бывает личной или общей `static` |
| **Метод** | Действие или вычисление |
| **Конструктор** | Инициализация нового экземпляра; имя совпадает с классом |
| **Ссылка** | Значение доступа к объекту либо `null` |
| **Параметр** | Переменная объявления метода или конструктора |
| **Аргумент** | Переданное при вызове значение или выражение |

## Общая форма

Шаблон, а не готовый файл:

```text
class ИмяКласса {
    private Тип имяПоля;
    ИмяКласса(Тип имяПараметра) {
        this.имяПоля = имяПараметра;
    }
    public void имяДействия() {
        инструкции;
    }
}

ИмяКласса имяПеременной = new ИмяКласса(аргумент);
имяПеременной.имяДействия();
```

Собственные имена выбирает программист и согласует объявления с обращениями. `class`, `private`, `this`, `new` и другие слова языка не переименовываются. Инструкции создания и вызова в наших примерах помещаются в `main`.

## Два объекта и три ссылки

Фрагмент из первой полной программы лекции; класс Phone объявлен там же:

```java
Phone anna = new Phone("Анна", 80);
Phone boris = new Phone("Борис", 50);
Phone partner = anna;
partner.use();
```

Создано два Phone. `partner` и `anna` ведут к одному объекту. После действия его заряд 70; заряд Бориса остаётся 50. `anna == partner` даёт true. Общее поле `createdCount` равно 2.

Присваивание копирует значение ссылки, а не клонирует объект. Java передаёт аргументы по значению, в том числе копируя значения ссылок.

## Четыре идеи

| Идея | Основной вопрос | Пример |
|---|---|---|
| **Инкапсуляция** | Как сохранить допустимое состояние и управлять доступом? | Закрытый заряд, проверки и `use()` |
| **Абстракция** | Что существенно и какой контракт нужен? | Действие устройства `work()` |
| **Наследование** | Является ли тип разновидностью другого? | `Phone extends Device` |
| **Полиморфизм** | Как общее обращение выбирает разное поведение? | Один `device.work()` вызывает реализацию фактического объекта |

Абстракция — идея, `abstract` — инструмент языка. `private` управляет доступом, но не заменяет проверки значений. Геттер и сеттер каждому полю не обязательны.

В учебном Phone допустим заряд от 0 до 100. При заряде меньше 10 `use()` выходит без вычитания; при 10 оставляет 0. Сохраняемое правило допустимого состояния — **инвариант**.

## Общий тип и конкретная реализация

Шаблон:

```text
abstract class Родитель {
    public abstract void действие();
}
class Потомок extends Родитель {
    @Override
    public void действие() {
        конкретные инструкции;
    }
}
Родитель имяСсылки = new Потомок();
имяСсылки.действие();
```

Имена заменяются согласованно. Конкретное тело зависит от задачи. `abstract`, `extends` и существующая аннотация `@Override` не заменяются произвольными словами.

Тип переменной определяет доступные обращения при проверке компилятором. Для переопределённого экземплярного метода реализация выбирается по фактическому объекту во время выполнения. Это правило нельзя автоматически переносить на поля, конструкторы и статические методы.

Абстрактный класс может иметь поля, конструктор и готовые методы. Напрямую создавать его экземпляр через `new Родитель()` нельзя. `super(...)` вызывает конструктор родителя при инициализации одного экземпляра потомка, а не создаёт второй самостоятельный объект.

## Не путать

- **Перегрузка**: варианты метода различаются параметрами. **Переопределение**: своя реализация унаследованного экземплярного метода с подходящей сигнатурой.
- `static` относится к классу; обычное личное поле — к экземпляру. Счётчик созданий не равен автоматически числу живых объектов.
- Наследование описывает «является разновидностью». Связь «содержит компонент» рассматривается отдельно: телефон содержит аккумулятор, но не является аккумулятором.
- Поле-ссылка само по себе не доказывает строгую композицию UML с общим жизненным циклом.
- `return` и вывод в консоль — разные действия.

## Проверка понимания

1. Нарисуй три ссылки и два объекта из первого опыта.
2. Объясни, почему `partner = boris` меняет получателя следующего действия.
3. Назови конкретные проверки, сохраняющие диапазон заряда.
4. Объясни, почему `Device device = new Phone(...)` допустимо во втором опыте.
5. Добавь третий вид устройства с `work()`, сохранив тело общего цикла.
6. Различи тип переменной, класс объекта, состояние, действие и результат вызова.

Полные работающие программы, их вывод и подробный разбор находятся в основной лекции. Опыты с двумя разными реализациями Phone запускаются в отдельных папках.
