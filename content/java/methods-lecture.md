# Методы: объявление, вызов, параметры и возврат значения

> Тема 1.1.6 по программе. К этому моменту в курсе уже разобраны типы и операции ([[1 Типы данных и операции|лекция 1.1.1]]), ветвление ([[2 Условный оператор|лекция 1.1.3]]), а на практике ([[Колледж/Группы/КСП 09.02.07.39/JAWA/Лабораторные работы/Блок 1/ПР02 Циклы и массивы — Задание студенту|ПР02]]) — циклы и массивы. Всё это время весь код жил в одном месте — внутри `main`. Чем больше становится программа, тем очевиднее проблема: `main` разрастается в длинную нечитаемую простыню, а одинаковые куски кода (например, поиск максимума в массиве) приходится копировать заново там, где они снова нужны. Методы — способ этого избежать.

## 1. Зачем нужны методы

Откройте мысленно `ArrayWork` из ПР02: там были отдельные куски кода для суммы, среднего, максимума, минимума, подсчёта по условию — все один за другим внутри одного `main`. Если бы в той же программе понадобилось посчитать статистику ещё для **второго** массива, пришлось бы либо копировать весь этот код второй раз (и почти наверняка где-то ошибиться при копировании), либо вынести каждый расчёт в отдельный именованный блок, который можно **вызвать** сколько угодно раз для любого массива. Второй путь — это и есть методы.

**Метод — это именованный блок кода, который можно вызвать по имени столько раз, сколько нужно, передав ему разные данные каждый раз.** Метод объявляется один раз, а используется — сколько угодно.

Вы уже пользовались методами с самого начала курса, просто как «готовыми чёрными ящиками»: `System.out.println(...)`, `scanner.nextInt()`, `Integer.parseInt(...)`, `numbers.length` — то есть нет, `length` не метод, а вот `String.valueOf(...)` — метод, и `Math.round(...)` тоже был бы методом. Сегодня — как объявлять **свои**.

## 2. Анатомия объявления метода

```java
static int square(int n) {
    int result = n * n;
    return result;
}
```

Разберём каждое слово по порядку:

- **`static`** — то же самое ключевое слово, что вы уже видели в заголовке `main`: `public static void main(String[] args)`. Оно означает «этот метод принадлежит классу целиком, а не какому-то отдельному объекту» — вызывать его можно напрямую по имени, без создания объекта через `new`. Полноценно про разницу между `static`-методами и методами объектов расскажем в теме 1.2.1 «Классы и объекты», когда появится сам смысл создавать объекты; пока что **все свои методы в этом курсе объявляем как `static`** — точно так же, как уже объявлен `main`, и вызываем их прямо по имени из `main` того же класса.
- **`int`** (перед именем метода) — **тип возвращаемого значения**. Метод обязан вернуть значение именно этого типа — не `String`, не `boolean`, не что-то ещё, а именно `int`. Если метод ничего не возвращает, здесь пишется специальное слово `void` (см. раздел 3).
- **`square`** — имя метода. Как и у переменных, имена методов пишутся в стиле camelCase — с маленькой буквы, каждое следующее слово с заглавной (`square`, `findMax`, `isEven`). Имя должно описывать, **что делает** метод, а не как он это делает — по хорошему имени понятно назначение метода, даже не заглядывая внутрь.
- **`(int n)`** — список **параметров** в круглых скобках: данные, которые метод получает на входе. Здесь один параметр `n` типа `int`. Скобки обязательны, даже если параметров нет вообще — тогда пишутся просто пустые `()`.
- **`{ ... }`** — тело метода, точно так же, как тело `if` или цикла — блок инструкций, которые выполнятся при вызове.
- **`return result;`** — команда, которая немедленно завершает выполнение метода и передаёт указанное значение туда, откуда метод был вызван. Тип значения после `return` должен совпадать с типом, объявленным перед именем метода (здесь — `int`).

## 3. Методы без возврата значения — `void`

Если метод должен что-то **сделать** (например, напечатать что-то в консоль), но ему не нужно ничего **возвращать** обратно вызывающему коду — вместо типа возврата пишется `void` («пустота»):

```java
static void printSquare(int n) {
    int result = n * n;
    System.out.println("Квадрат числа " + n + " = " + result);
}
```

У `void`-метода `return;` (без значения после него) необязателен, но допустим — например, чтобы досрочно прервать выполнение метода внутри `if`, точно так же, как `return` иногда используется внутри `if` в обычных функциях:

```java
static void printPositiveSquare(int n) {
    if (n < 0) {
        System.out.println("Число отрицательное, квадрат не считаем");
        return; // выходим из метода, дальше код не выполнится
    }
    System.out.println("Квадрат числа " + n + " = " + (n * n));
}
```

Написать `return result;` (со значением) внутри `void`-метода — ошибка компиляции: компилятор считает это противоречием («ты же обещал ничего не возвращать») и не позволит такой код запустить.

## 4. Методы с возвратом значения — та же задача, другой подход

Сравните два метода из разделов 2 и 3 — они делают **одно и то же вычисление** (квадрат числа), но по-разному распоряжаются результатом:

```java
static void printSquare(int n) {          // печатает сам, ничего не возвращает
    System.out.println("Квадрат: " + (n * n));
}

static int square(int n) {                 // возвращает число, ничего не печатает
    return n * n;
}
```

`printSquare` **решает сам**, что делать с результатом — печатает его. Вызвать его и как-то использовать результат дальше в коде нельзя, потому что результата (в виде значения) у него просто нет. `square` результат ничего не делает с ним сам — он **отдаёт** значение туда, откуда его вызвали, а что с этим значением делать дальше — решает вызывающий код:

```java
public static void main(String[] args) {
    int result = square(5);              // сохранили в переменную
    System.out.println("Результат: " + result);

    if (square(4) > 10) {                // использовали прямо в условии
        System.out.println("Квадрат больше 10");
    }

    System.out.println(square(3) + square(4)); // использовали в выражении
}
```

Это и есть главное преимущество функции (метода с возвратом) над процедурой (`void`-методом): результат функции можно передавать дальше, комбинировать с другими значениями, использовать в условиях — то есть встраивать в остальной код, а не быть жёстко привязанным к одному конкретному действию (печати).

> Старая терминология (ещё до объектно-ориентированных языков) называла `void`-методы **процедурами**, а методы с возвратом значения — **функциями**. В Java формально и то, и другое называется просто «методом» — но термины «процедура»/«функция» по-прежнему часто используют неформально, в том числе в этом курсе, потому что разница в поведении (возвращает что-то или нет) — реальная и важная.

## 5. Параметры: сколько угодно, и они могут быть разных типов

Метод может принимать несколько параметров, перечисленных через запятую — каждый со своим типом:

```java
static int add(int a, int b) {
    return a + b;
}

static double calculateAverage(int sum, int count) {
    return (double) sum / count;
}
```

Обратите внимание на `calculateAverage` — это ровно та же логика, что была в ПР02 внутри `main` (включая то же самое `(double)` перед делением, по той же причине: `int / int` без приведения дало бы обрубленный результат). Разница только в том, что теперь это отдельный именованный метод, который можно вызвать для любых `sum` и `count`, а не код, намертво привязанный к одной конкретной переменной `numbers` внутри одного `main`.

При вызове метода количество и типы переданных значений (**аргументов**) должны точно соответствовать тому, что объявлено в параметрах (это называется **сигнатурой** метода) — `add(2, 3)` подходит, `add(2)` (не хватает аргумента) или `add("2", "3")` (не те типы) не скомпилируются.

## 6. Вызов метода

Внутри одного класса методы можно вызывать друг у друга просто по имени, без каких-либо дополнительных слов впереди — компилятор ищет метод с таким именем и подходящей сигнатурой прямо в этом же классе:

```java
public class MethodsDemo {
    public static void main(String[] args) {
        int sum = add(10, 20);
        System.out.println("Сумма: " + sum);
    }

    static int add(int a, int b) {
        return a + b;
    }
}
```

Важная деталь, которая отличает методы от переменных: метод `add` объявлен **ниже** `main`, но вызван из `main` **выше** — и это прекрасно работает. В отличие от переменных (которые обязательно должны быть объявлены раньше первого использования), Java сначала «видит» вообще все методы класса целиком, а только потом начинает выполнять `main` — поэтому порядок расположения методов в файле не имеет значения для компиляции. Тем не менее общепринятая практика — располагать `main` первым, а вспомогательные методы ниже, просто для удобства чтения человеком.

## 7. Перегрузка методов (overloading) — коротко

В Java можно объявить **несколько методов с одинаковым именем**, если у них разное количество параметров или разные типы параметров — это называется **перегрузкой**:

```java
static String describe(int n) {
    return (n % 2 == 0) ? "чётное" : "нечётное";
}

static String describe(int n, int divisor) {
    return (n % divisor == 0) ? "делится на " + divisor : "не делится на " + divisor;
}
```

При вызове `describe(7)` или `describe(7, 3)` Java сама определяет, какой из двух методов имелся в виду — по количеству и типам переданных аргументов, компилятор подбирает подходящую сигнатуру автоматически, вам не нужно как-то дополнительно уточнять, какую версию вызвать. Перегрузка — это удобство для того, кто **вызывает** метод: не нужно запоминать разные имена (`describeSimple`, `describeWithDivisor`) для по сути одной и той же смысловой операции.

## 8. Частые ошибки

| Ошибка | Что происходит | Как избежать |
|---|---|---|
| Тип возврата `int`, а в методе нет `return` на каком-то из путей выполнения (например, `return` только внутри `if`, без `else`) | Ошибка компиляции: `missing return statement` | Убедиться, что метод возвращает значение при **любом** возможном пути выполнения — если есть `if`, должен быть и `else`, либо `return` после всей конструкции |
| `return` со значением внутри `void`-метода | Ошибка компиляции: несовместимые типы | В `void`-методе `return` — либо вообще без значения, либо не писать его совсем |
| Не совпадает количество или порядок аргументов при вызове (`calculateAverage(count, sum)` вместо `calculateAverage(sum, count)`) | Либо ошибка компиляции (если типы явно не подходят), либо, что опаснее — код скомпилируется, но посчитает неверный результат, если типы параметров случайно совпадают (оба `int`) | Внимательно сверять порядок параметров с объявлением метода при каждом вызове |
| Забыли использовать (никуда не записали и не вывели) результат функции с возвратом | Компилятор не ругается — вызвать `square(5);` без сохранения результата совершенно законно, просто бессмысленно | Не ошибка сама по себе, но повод перепроверить логику: если вызываете функцию (не `void`) и не используете результат, скорее всего, вы либо хотели `void`-метод, либо забыли `int result = ...` |
| Путают тип возврата метода с типом параметра | Например, объявили `static int printSquare(int n)`, хотя метод ничего не возвращает | Тип **перед именем метода** — это то, что метод отдаёт наружу; типы **внутри скобок** — то, что метод получает на входе; это две независимые вещи |

## 9. Итог лекции

Метод — именованный блок кода, объявляемый один раз и вызываемый сколько угодно раз с разными данными. Ключевые части объявления — `static` (пока используем всегда, полноценно разберём в теме 1.2.1), тип возврата (`void`, если метод ничего не отдаёт, либо конкретный тип, если отдаёт — тогда внутри обязателен `return` с значением этого типа на каждом возможном пути выполнения), имя в camelCase и список параметров в скобках. Методы без возврата исторически называют процедурами, с возвратом — функциями; разница не только в терминах, а в том, что результат функции можно использовать дальше в коде (сохранять, сравнивать, комбинировать), а результат процедуры — нельзя, потому что его просто нет. Перегрузка позволяет нескольким методам делить одно имя, если у них разные сигнатуры. Дальше на практике (ПР03) — рефакторинг кода из ПР02 в отдельные методы, чтобы увидеть разницу «всё в одном `main`» vs «код, разложенный по именованным методам», своими руками.

**Проверь себя:**

1. Чем метод `static int square(int n) { return n * n; }` принципиально отличается от `static void printSquare(int n) { System.out.println(n * n); }`, если оба «по сути» считают квадрат числа?
2. Почему следующий метод не скомпилируется: `static int abs(int n) { if (n < 0) { return -n; } }` — и как его исправить?
3. Что выведет `System.out.println(add(2, 3) + add(4, 5));`, если `add` объявлен как в разделе 6 — и почему здесь корректно использовать результат функции прямо внутри выражения?
4. В разделе 7 показана перегрузка `describe(int n)` и `describe(int n, int divisor)`. Что произойдёт, если вызвать `describe(7, 3, 2)` — метод с тремя параметрами не объявлен?
5. Метод `add` объявлен ниже `main`, но вызывается из `main`, который идёт раньше по тексту файла. Почему это допустимо для методов, но было бы ошибкой, попробуй вы использовать переменную до её объявления?

7. Придумайте пример ситуации (не обязательно из программирования), где было бы удобнее получить от кого-то готовый результат («функция»), а не попросить кого-то сразу что-то сделать и объявить результат вслух («процедура») — и наоборот.
