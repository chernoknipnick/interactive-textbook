# Обзор языков программирования: какие бывают и для чего каждый нужен

> Предшествует [[0 Введение в курс|Введению в курс]]. Цель — до того, как мы погрузимся в Java и Kotlin, увидеть картину целиком: почему языков программирования сотни, чем они отличаются друг от друга и почему для мобильной разработки выбраны именно эти два.

## 1. Зачем нужно много языков программирования, если можно один

Логичный вопрос: если все языки в итоге заставляют процессор выполнять одни и те же операции (сложить числа, сравнить, перейти к другой инструкции), зачем их сотни? Ответ — разные языки решают разные задачи разной ценой: одни дают максимальный контроль над железом и скорость (но требуют больше кода и внимания), другие — максимальную скорость написания кода (но жертвуют производительностью или контролем над ошибками). Универсального «лучшего» языка не существует — есть более и менее подходящий для конкретной платформы и задачи.

## 2. Как язык превращается в работающую программу: компиляция, интерпретация, байт-код

**Компилируемые языки** (C, C++, Rust, Go) переводятся в машинный код *целиком, заранее*, специальной программой-компилятором. Результат — исполняемый файл, который процессор выполняет напрямую, без посредников. Плюс — максимальная скорость выполнения. Минус — под каждую операционную систему и архитектуру процессора нужна отдельная сборка.

**Интерпретируемые языки** (классический Python, PHP до определённой версии, Ruby) выполняются построчно специальной программой-интерпретатором в момент запуска, без отдельного шага компиляции в машинный код. Плюс — один и тот же файл с кодом работает где угодно, где есть интерпретатор; можно менять код и сразу видеть результат. Минус — медленнее компилируемых языков, потому что перевод в машинные операции происходит на лету.

**Гибридный подход — байт-код и виртуальная машина** (Java, Kotlin, C#): код сначала компилируется не в машинный код конкретного процессора, а в промежуточный **байт-код** — универсальный набор инструкций. Дальше этот байт-код выполняет **виртуальная машина** (для Java и Kotlin — JVM, Java Virtual Machine), которая уже во время выполнения переводит байт-код в машинные инструкции конкретного процессора (JIT-компиляция, just-in-time). Это соединяет плюсы обоих подходов: код, скомпилированный один раз в байт-код, работает на любой платформе, где есть JVM, а скорость благодаря JIT приближается к полностью компилируемым языкам. **Именно так работают и Java, и Kotlin** — языки этого курса.

## 3. Типизация: когда язык проверяет, что вы не перепутали типы данных

**Статическая типизация** (Java, Kotlin, C++) — тип переменной известен и проверяется **до** запуска программы, на этапе компиляции. Ошибка вида «попытка сложить число со строкой» обнаружится сразу, ещё до того, как программа хоть раз запустится.

**Динамическая типизация** (Python, PHP, JavaScript) — тип определяется во время выполнения, переменная может в разные моменты хранить значения разных типов. Быстрее писать код, но некоторые ошибки типов всплывают только во время работы программы, иногда — у реального пользователя.

Отдельная ось — **строгая/слабая типизация**: строгая (Java, Kotlin, Python) не позволяет неявно «превратить» одно в другое без явной команды (умножить строку на число — ошибка); слабая (классический JavaScript, PHP в ряде мест) допускает молчаливые неявные преобразования, что удобно, но иногда становится источником трудноуловимых багов. Java и Kotlin — оба строго и статически типизированы, что и разбирается подробно в лекции [[1 Типы данных и операции|«Типы данных и операции»]].

## 4. Парадигмы программирования: разные способы мышления о коде

- **Процедурное программирование** — программа как последовательность инструкций и вызовов функций (классический C).
- **Объектно-ориентированное программирование (ООП)** — данные и логика объединяются в объекты, у объектов есть классы, наследование, полиморфизм (Java, Kotlin, C++, Python). Это основной стиль всего курса — подробно в разделе [[Колледж/Группы/КСП 09.02.07.39/JAWA/Лекции/2 Второй вводный блок в ЯП JAWA введение в ООП/Классы и объекты.|«Классы и объекты»]] и далее.
- **Функциональное программирование** — программа как вычисление функций без изменяемого состояния (чистый Haskell; элементы функционального стиля есть и в Kotlin — лямбды, неизменяемые `val`).
- **Декларативное программирование** — вы описываете *что* нужно получить, а не *как* это сделать шаг за шагом. Классический пример — язык SQL: запрос `SELECT * FROM users WHERE age > 18` не описывает алгоритм поиска, а декларирует результат — этим языком мы будем пользоваться в теме про SQLite.

Kotlin особенно интересен тем, что сочетает ООП с элементами функционального стиля — то, что в Java часто требует громоздкого кода (например, обработка списка через циклы), в Kotlin делается в одну строку функциональными операциями (`map`, `filter`).

## 6. Место Java и Kotlin в этой картине

Java появилась в 1995 году как язык «write once, run anywhere» — благодаря JVM один и тот же байт-код работает на любой платформе, для которой есть виртуальная машина (подробная история — в лекции [[Колледж/Группы/КСП 09.02.07.39/JAWA/Лекции/1 Первый  блок. Вводная часть ЯП  JAWA/История создания ЯП|«История создания языка»]]). Android изначально строился именно на Java — виртуальная машина Android (сначала Dalvik, затем ART) выполняет тот же байт-код по той же логике.

Kotlin появился в 2011 году как язык от JetBrains, тоже компилируется в JVM-байт-код и **полностью совместим с Java** — можно в одном проекте использовать оба языка одновременно, вызывать Java-код из Kotlin и наоборот. В 2019 году Google объявила Kotlin приоритетным (`Kotlin-first`) языком для новой Android-разработки. Поэтому у нас не «два курса в одном», а один: тот же байт-код, та же платформа, та же JVM — просто два синтаксиса для описания одной и той же логики, и оба вам пригодятся на практике.
