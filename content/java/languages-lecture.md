# Обзор языков программирования

## Сначала пойми задачу: язык — способ записать решение

Представь, что нужно посчитать стоимость покупки. Человек формулирует правило словами: «Возьми цену одной вещи и умножь на количество». Для программы правило должно быть записано точно: какие исходные данные есть, какую операцию выполнить и что показать.

**Алгоритм** — понятная последовательность действий для решения задачи. **Программа** — запись решения на языке, которую можно подготовить к выполнению в выбранной среде. **Язык программирования** задаёт допустимые записи и их смысл. **Среда выполнения** помогает подготовленному коду работать. Эти понятия связаны, но не взаимозаменяемы: Java — язык, JVM — часть среды выполнения, IntelliJ IDEA — инструмент для написания кода.

## Общая форма: смысл задачи и конкретная запись

Это описание идеи, а не готовый код Java:

```text
получить исходные данные
выполнить вычисление
показать результат
```

А это три инструкции Java внутри main:

```java
int price = 120;
int count = 3;
System.out.println(price * count);
```

price и count — имена, выбранные автором. Можно выбрать ticketPrice и ticketCount, согласованно изменив обращения. int и знаки `=`, `;`, `*` принадлежат правилам языка. println — имя готового метода; произвольное другое имя вместо него не заработает.

Здесь важно увидеть общую идею, а не выучить синтаксис раньше времени. Следующие темы отдельно объяснят каждую конструкцию.

## Одна маленькая программа целиком

```java
public class LanguageDemo {
    public static void main(String[] args) {
        int price = 120;
        int count = 3;
        int total = price * count;
        System.out.println(total);
    }
}
```

Файл называется LanguageDemo.java. Для обычного запуска из его папки выполни `javac LanguageDemo.java`, затем `java LanguageDemo`. Вывод — **360**.

| Строка внутри main | Что происходит | Что пока не происходит |
|---|---|---|
| `int price = 120;` | Создаётся локальная переменная с целым значением 120 | На экран ничего не выводится |
| `int count = 3;` | Сохраняется количество | Покупка автоматически не оформляется |
| `int total = price * count;` | Читаются 120 и 3, вычисляется 360, результат сохраняется | total не является самой формулой «навсегда»: это вычисленное значение |
| `println(total)` | Значение передаётся методу вывода | Исходные переменные не меняются |

Полная запись `System.out.println` в исходнике обязательна для этого примера; сокращённое обозначение в таблице нужно только для чтения.

## Что происходит между файлом и работающей программой

**Исходный код** — текст, который ты написал. **Компилятор** проверяет его и переводит в другой вид. Для привычного Java-проекта javac создаёт файлы `.class` с байт-кодом. **Байт-код** — инструкции для виртуальной машины, а не текст Java и не универсальные инструкции любого физического процессора.

JVM загружает подготовленные классы и выполняет программу. В распространённых реализациях часть кода может интерпретироваться, а часто выполняемые участки компилироваться JIT-компилятором в машинный код. Поэтому разделение языков на «всегда компилируемые» и «всегда построчно интерпретируемые» слишком грубое: многое зависит от реализации.

Например, CPython обычно сначала получает байт-код Python, затем исполняет его. Это не javac и не JVM. Наличие промежуточного представления само по себе не делает среды одинаковыми.

## Компиляция и запуск — не одно действие

Если потерять `;`, ошибка появится при компиляции: до нормального запуска дело не дойдёт. Если правильно скомпилировать программу, которая при выполнении делит целое число на ноль, возможна уже ошибка выполнения. А если вместо умножения написать сложение, программа может успешно запуститься и дать неверное по задаче число. Это **логическая ошибка**.

Сначала проверь, какой именно этап не удался. Поиск «ошибки в компьютере» без такого различия обычно только запутывает.

## Типизация: два отдельных вопроса

Статическая типизация означает, что допустимость многих операций проверяется по типам до выполнения. Динамическая переносит больше таких проверок на время выполнения. Это не вопрос «указывает ли программист тип руками»: тип можно выводить автоматически, сохраняя статическую проверку.

```java
int count = 3;
String label = "Билетов: " + count;
```

Эта запись допустима: Java специально поддерживает соединение строки с представлением числа. Поэтому фраза «в статически типизированном языке нельзя сложить число со строкой» неверна без уточнения операции и правил языка. А `int count = "три";` не подходит: строка не является значением int.

Термины «сильная» и «слабая» типизация используются неодинаково в разных источниках. Полезнее спрашивать конкретно: разрешено ли неявное преобразование, какая операция выполняется и когда возникает ошибка.

## Почему Java на компьютере и Android — не буквально одна среда

В настольных примерах курса `.class` выполняются на JVM. В сборке Android код проходит дополнительные преобразования в формат DEX и входит в пакет приложения; на устройстве используется среда ART. Android не запускает обычные `.class` так, как команда java в наших консольных опытах.

Java и Kotlin/JVM могут взаимодействовать в одном проекте, но «совместимы» не означает, что любой код автоматически работает на любой платформе. Имеют значение библиотеки, версии, настройки сборки и доступные API. Kotlin имеет и другие целевые платформы, а не только JVM.

## Как выбирать язык без соревнования «кто лучше»

Начни с ограничений задачи: где программа будет работать, какие библиотеки нужны, какой код уже есть и кто его поддерживает. Для браузерного интерфейса важна браузерная платформа, для Android — инструменты Android, для анализа таблиц — библиотеки работы с данными.

Сначала выбери платформу и задачу, затем сравни инструменты. Таблица языков ниже — ориентир по распространённым применениям, а не запрет использовать язык где-либо ещё.

| Язык | Где часто встречается | Что важно различать |
|---|---|---|
| Java | Серверные и консольные приложения, часть Android-проектов | Язык Java и среда JVM — разные понятия |
| Python | Автоматизация, анализ данных, серверные приложения | Библиотека решает свою задачу; короткая запись не отменяет проверку алгоритма |
| JavaScript | Код веб-страниц; серверные приложения в подходящей среде | JavaScript не является сокращением или разновидностью Java |
| C# | Приложения на платформе .NET | Похожий синтаксис не делает библиотеки Java и .NET взаимозаменяемыми |
| C++ | Системные компоненты и приложения с требованиями к управлению ресурсами | Правила времени жизни и памяти отличаются от начальных Java-примеров |
| SQL | Запросы к данным в СУБД | Обычно описывает, какой набор данных нужен; это другой вид задачи, чем консольная программа |

**Парадигма** — подход к организации решения. В императивном стиле описываются действия и изменения состояния. В объектном стиле связанные данные и действия организуют через объекты. В функциональном стиле важны вычисления через функции и работа с результатами выражений. Один современный язык может поддерживать несколько подходов: это не три взаимоисключающие коробки.

В начале курса мы изучаем последовательность действий и переменные. Затем классы и объекты помогут организовать более крупную программу. Название подхода само по себе не делает решение правильным: результат всё равно проверяется на конкретных входных данных.

## Попробуй сам: меняй одно условие за раз

1. Предскажи вывод при price = 150 и count = 2, затем проверь.
2. Замени имя count на quantity во всех нужных местах. Вывод должен сохраниться.
3. Поменяй только `*` на `+`. Объясни, почему компилятор не обязан заметить ошибку постановки задачи.
4. Назови отдельно язык, компилятор, среду выполнения и редактор в своём способе запуска.

Если можешь объяснить каждое изменение, ты уже читаешь программу как решение задачи, а не как набор незнакомых слов.
