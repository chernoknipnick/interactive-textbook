# 1.2.1 Классы и объекты

## Основные понятия



> **Класс** — описание типа объектов: какие данные они хранят и какие действия доступны для них.

>

> **Объект** — конкретный экземпляр класса со своим состоянием. У одного класса может быть много объектов.

>

> **Поле объекта** — переменная, принадлежащая конкретному объекту и хранящая часть его состояния.

>

> **Метод объекта** — действие, вызываемое для конкретного объекта и способное работать с его состоянием.

>

> **`this`** — ссылка на текущий объект внутри его экземплярного метода или конструктора.

>

> **Инкапсуляция** — объединение данных и поведения в классе и управление доступом к состоянию через выбранный интерфейс.



## Общая форма: что задаёт Java, а что выбираешь ты

В примерах используются конкретные имена Student, anna, energy и study. Они не являются обязательными словами Java. Это имена, которые выбрал автор программы. Ниже — шаблоны, помогающие увидеть устройство конструкций.

### Объявление класса, поля и метода

Следующая запись — **общая форма, а не готовая программа**. Подписи вроде «ИмяКласса» и «ТипПоля» нужно заменить подходящими именами и типами, а многоточие — настоящими инструкциями.

```text
class ИмяКласса {
    ТипПоля имяПоля;

    ТипРезультата имяМетода(ТипПараметра имяПараметра) {
        ...
    }
}
```

| Часть | Что здесь можно выбирать | Какое правило нужно сохранить |
|---|---|---|
| `class` | Это слово не переименовывается | Оно начинает объявление класса |
| `ИмяКласса` | Student, Robot, Phone или другое допустимое имя | Одно и то же имя согласованно используется в объявлении и обращениях к типу |
| `ТипПоля` | Подходящий существующий тип: например, int, String или Student | Тип ограничивает допустимые значения поля |
| `имяПоля` | energy, battery, speed и другое понятное имя | При обращении к этому полю используется именно объявленное имя |
| `ТипРезультата` | Тип ответа метода либо void для действия без результата | Если обещан результат, метод должен возвращать подходящее значение на каждом нормальном пути завершения |
| `имяМетода` | study, move, charge и другое допустимое имя собственного метода | Имя при вызове должно совпадать с объявлением |
| Параметры | Их типы, имена и количество определяются задачей | Если параметров нет, круглые скобки остаются пустыми |
| `{ }`, `( )`, `;` | Это знаки синтаксиса | Их нельзя заменить произвольными словами или забыть |

### Создание объекта и обращения к нему

```text
ИмяКласса имяПеременной = new ИмяКласса();
имяПеременной.имяПоля = значение;
имяПеременной.имяМетода(аргументы);
```

Это схема **простого случая без наследования**: справа создаётся объект того же класса, который указан слева. Позже ты узнаешь случаи, когда тип переменной и создаваемый класс могут различаться.

Вместо имени переменной anna можно выбрать learner, firstStudent или другое допустимое имя. Вместо собственного метода study можно объявить learn. Но после переименования **и объявление, и вызов** должны совпадать: метод learn вызывается как `learner.learn()`, а не как `learner.study()`.

```java
class Robot {
    int battery;

    void move() {
        battery -= 10;
    }
}
```

Код использования внутри main:

```java
Robot helper = new Robot();
helper.battery = 70;
helper.move();
System.out.println(helper.battery);
```

Вывод — 60. Сравни со Student: Robot — выбранный тип, helper — переменная со ссылкой, battery — поле, move — метод. Структура та же, конкретные имена и предметная задача другие. В этом маленьком примере move вызывается при заведомо достаточном заряде; проверка заряда понадобилась бы для общего решения.

### Что нельзя переименовать просто по желанию

Собственные имена выбираешь ты. Готовые имена API задаёт библиотека: `System.out.println` нельзя заменить на `System.out.сказать`, если такого метода у потока нет. В принятой здесь форме запуска JVM ищет `main`; после произвольного переименования точка входа не будет найдена этой командой. Имя конструктора должно совпадать с именем класса — это отдельное правило, которое ты разберёшь в следующей теме.

Для учебных имён удобно использовать латинские буквы, цифры и подчёркивание; имя не начинается с цифры и не совпадает с ключевым словом. Java различает регистр: study и Study — разные имена. Классы обычно называют с большой буквы, поля и методы — с маленькой. Это соглашение для понятного чтения; ключевые слова и корректный синтаксис — уже требования языка.

Проверь себя: если переименовать Student в Robot, anna в helper, energy в battery и study в move, что останется прежним? Ответ: устройство объявления, создания, доступа через точку и вызова метода. Чтобы программа работала, согласованно меняются все связанные обращения.

## 1. Зачем класс, если уже есть переменные

«У одного персонажа игры есть имя и энергия. Пока он один, напишем две переменные. Но если персонажей двадцать, отдельно хранить имена и энергию опасно: легко перепутать, кому принадлежит число. Нам нужна карточка, в которой связанные данные находятся вместе».

Представь четыре отдельные переменные: `annaName`, `annaEnergy`, `borisName`, `borisEnergy`. Как добавить ещё сто студентов? Два параллельных массива возможны, но тебе придётся следить, чтобы одинаковые индексы означали одного человека. Класс выражает эту связь напрямую: имя и энергия принадлежат одному объекту.

Пустой шаблон карточки — класс. Заполненная карточка Анны — объект. Заполненная карточка Бориса — другой объект. Сам шаблон не является ни Анной, ни Борисом. У аналогии есть ограничение: программный объект содержит ещё и доступное поведение, а не только подписи в анкете.

## 2. Сначала самый маленький класс

```java
class Student {
    String name;
    int energy;
}
```

Разберём каждую часть: `class` начинает описание, `Student` — имя нового типа, фигурные скобки ограничивают тело класса. Поля объявляются внутри класса, но вне методов. Большая буква в имени класса — соглашение об именовании. `Student` — тип, как `String`, а `anna` будет именем переменной.

Описание класса ещё не создаёт объекты `Student`. Пустая форма карточки может существовать даже до того, как мы заполнили первую карточку.

## 3. Четыре действия, спрятанные в одной строке

```java
Student anna = new Student();
```

Прочитай строку по частям: `Student` — допустимый тип ссылки; `anna` — имя переменной; `new Student()` — создание объекта; `=` — сохранение полученной ссылки. Попробуй выделить эти части разными цветами в своей записи.

Сначала выражение справа создаёт и инициализирует объект, затем полученная ссылка присваивается переменной слева. Переменная не содержит «всего студента внутри себя». Она позволяет найти объект.

В этом минимальном классе конструкторы не написаны, поэтому Java предоставляет конструктор по умолчанию. Скобки относятся к вызову конструктора в выражении создания, а не к вызову класса как обычного метода. Конструкторы подробно разобраны в следующей теме.

```java
anna.name = "Анна";
anna.energy = 70;
Student boris = new Student();
boris.name = "Борис";
boris.energy = 40;
```

Точка читается «у этого объекта». `anna.energy` — энергия объекта, к которому ведёт `anna`. `boris.energy` — энергия другого объекта. Две записи `new Student()` создали два объекта с независимыми экземплярными полями.

«Изменили `anna.energy`. Должен ли измениться Борис?» Нет: это другой объект. «Всегда ли две переменные означают два объекта?» Нет: повторить предыдущую тему про ссылки.

## 4. Поля и локальные переменные

Поля `String name` и `int energy` получают начальные значения `null` и 0 до наших присваиваний. Это не означает, что Java автоматически дала студенту осмысленное имя или допустимое состояние.

Локальная переменная в методе не получает такого автоматического разрешения на чтение: `int energy; System.out.println(energy);` не скомпилируется. Одно и то же имя типа не делает поля и локальные переменные одинаковыми по правилам инициализации.

Проверь самостоятельно: создай Student и до заполнения выведи оба поля. Ты увидишь `null` и 0. Затем присвой имя и энергию и сравни вывод. Не вызывай метод у `name`, пока там `null`: строкового объекта за этой ссылкой ещё нет.

## 5. Метод: действие, у которого есть хозяин

Добавляем в тело `Student`:

```java
void study() {
    if (energy < 10) {
        System.out.println(name + ": сначала нужен отдых");
        return;
    }
    energy -= 10;
    System.out.println(name + " учится. Энергия: " + energy);
}
```

«Текст метода написан один раз, но состояние зависит от получателя вызова». В `anna.study()` текущий объект — Анна. В `boris.study()` — Борис. Внутри `study` короткая запись `energy` обращается к полю текущего объекта; можно явно написать `this.energy`.

Здесь нет `static`: методу важно, **кто именно** учится. Не нужно копировать тело метода для каждой карточки. Метод описан классом, а работает с конкретным получателем вызова.

Проследи выполнение по строкам: условие проверяет возможность занятия; `return;` завершает вызов без результата; `energy -= 10` меняет поле; вывод показывает новое состояние. Если энергии ровно 10, занятие допустимо, результат — 0. Если 9 — состояние сохраняется.

Далее понадобятся два метода. `rest()` увеличивает энергию на 20, но не выше 100. `isTired()` возвращает результат проверки `energy < 30`. У `isTired` результат `boolean`, поэтому его удобно использовать прямо в `if`. Полный код обоих методов есть ниже; в разделе 17 ты разберёшь каждую строку.

## 6. Где находится main и как запустить

В полном примере ниже `ObjectsDemo` — публичный класс запуска, `Student` — второй класс в том же файле без `public`. Имя файла — `ObjectsDemo.java`. Это удобная учебная упаковка; обычно каждый класс размещают в своём файле.

Пока используем знакомую форму `public static void main(String[] args)`. `main` — место запуска сценария, а `Student` — описание участников сценария. Из `main` вызываем `anna.study()`, а не просто `study()`: нужен конкретный объект.

Представь вложенные рамки: файл содержит два соседних класса; внутри `Student` находятся поля и методы, а внутри `ObjectsDemo` — `main`. В этом примере объявление Student расположено снаружи main: ориентируйся на полную структуру файла ниже.

## 7. Один объект, две ссылки

```java
Student partner = anna;
partner.rest();
```

Нового студента нет: выполнено присваивание ссылки. Через `partner` вызван метод того же объекта Анны. Теперь `anna.energy` показывает изменённую энергию. Это тот же сюжет, что с массивом, только объект теперь имеет собственный класс.

```java
Student another = new Student();
another.name = "Анна";
another.energy = anna.energy;
```

Здесь другой объект, хотя данные могут совпадать. «Одинаковые данные» и «тот же экземпляр» — разные вопросы. `anna == partner` даст `true`; `anna == another` — `false`. У нашего класса `equals` пока не переопределён, поэтому не ждём от него сравнения всех полей.

## 8. Передаём студента в метод

Метод `help(Student learner)` может вызвать `learner.rest()`: изменится тот же объект, который передан при вызове. Но `learner = new Student()` переназначил бы только параметр. Тип `Student` не отменяет правил ссылок из предыдущего урока.

Пусть Анна имеет энергию 20, Борис — 40. Вызвать `help(anna)`. Предсказать энергии обоих до запуска. Ожидаются 40 и 40. Совпавшие числа не означают, что объекты слились.

## 9. Массив студентов: полки сначала пусты

```java
Student[] group = new Student[2];
group[0] = anna;
group[1] = boris;
```

Первая строка создаёт один массив из двух ссылочных ячеек, первоначально `null`. Она не создаёт двух студентов. Следующие строки помещают ссылки на уже существующие объекты. Изменение через `group[0]` видно через `anna`.

В итоговом примере для каждого элемента вызывается `study()`. В реальной работе при частично заполненном массиве сначала проверять `group[index] != null`. Здесь оба элемента явно заполнены.

## 10. Зачем закрывать поля

Открытые для пакета поля пока упрощают первый эксперимент. Но запись `anna.energy = -500` обходит правило про отдых и учёбу. На следующем уроке сделаем поля `private` и зададим безопасное создание через конструктор.

Инкапсуляция не сводится к автоматической генерации геттеров и сеттеров для всего. Важнее решить, какие действия вообще разрешены: для энергии могут быть лучше `study` и `rest`, чем возможность произвольно устанавливать любое число.

Позже ты познакомишься с наследованием, полиморфизмом и абстракцией. Сейчас твоя главная задача — понять один работающий объект: где его поля, как вызвать его метод и почему другая ссылка может вести к тому же экземпляру.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 ObjectsDemo.java`, затем `java ObjectsDemo`. JDK 17 или новее.

```java
public class ObjectsDemo {
    public static void main(String[] args) {
        Student anna = new Student();
        anna.name = "Анна";
        anna.energy = 70;
        Student boris = new Student();
        boris.name = "Борис";
        boris.energy = 40;
        anna.study();
        Student partner = anna;
        partner.rest();
        System.out.println(anna.energy);
        System.out.println(boris.energy);
        System.out.println(anna == partner);
        Student[] group = new Student[2];
        group[0] = anna;
        group[1] = boris;
        for (int index = 0; index < group.length; index++) {
            group[index].study();
        }
        System.out.println(boris.isTired());
    }
}
class Student {
    String name;
    int energy;
    void study() {
        if (energy < 10) {
            System.out.println(name + ": сначала нужен отдых");
            return;
        }
        energy -= 10;
        System.out.println(name + " учится. Энергия: " + energy);
    }
    void rest() {
        energy += 20;
        if (energy > 100) {
            energy = 100;
        }
    }
    boolean isTired() {
        return energy < 30;
    }
}
```

Ожидаемый вывод:

```text
Анна учится. Энергия: 60
80
40
true
Анна учится. Энергия: 70
Борис учится. Энергия: 30
false
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.

## 11. Словарь: не путать шесть разных вещей

| Слово | Простое объяснение | В нашей программе |
|---|---|---|
| Тип | Правило, какие значения допустимы и какие действия с ними можно делать | `int`, `String`, `Student` |
| Класс | Описание нового ссылочного типа и поведения его экземпляров | Объявление `class Student` |
| Объект | Конкретный экземпляр, который существует во время работы программы | Отдельный Student с именем «Анна» |
| Переменная | Именованное место для значения | `anna`, `index`, `partner` |
| Ссылка | Значение, позволяющее обратиться к объекту | Значение, сохранённое в `anna` |
| Поле | Переменная, принадлежащая объекту или классу; здесь пока объекту | `name` и `energy` каждого Student |

Когда говорим «объект Анна», это удобное сокращение: речь об экземпляре Student, поле `name` которого равно строке «Анна». Слово `anna` в исходнике — имя переменной, а текст `"Анна"` — значение поля. Объект не обязан знать, как назвали ведущую к нему переменную. Если вторую ссылку назвать `partner`, имя в карточке само не превратится в «partner».

У класса `Student` нет специального встроенного смысла «человек». Мы сами выбрали название и поля. Если написать `class Learner`, а затем везде согласованно заменить тип, модель останется такой же. В отличие от имён, слова `class`, `new`, `int`, `void`, `return` принадлежат языку Java: их нельзя произвольно переименовать.

### Зачем вообще связывать состояние и действия

Состояние отвечает на вопрос «что сейчас известно об объекте?»: имя — Анна, энергия — 70. Поведение отвечает на вопрос «что объекту можно поручить?»: учиться, отдыхать, проверить усталость. Метод может читать состояние, менять его, возвращать ответ или сочетать эти действия.

Не каждый объект обязан изображать вещь из физического мира. Объектом может быть заявка, игровой сеанс, настройка, заказ или соединение. Мы начинаем со студента только потому, что его карточку легко представить.

## 12. Самый маленький класс: каждое слово и знак

```java
class Student {
    String name;
    int energy;
}
```

| Фрагмент | Что именно означает |
|---|---|
| `class` | Начинаем объявление класса |
| `Student` | Имя объявляемого типа; регистр важен: `student` — другое имя |
| `{` после имени | Здесь начинается тело класса |
| `String` | Тип поля `name`; его значение — ссылка на строку либо `null` |
| `name` | Выбранное нами имя поля |
| `;` после поля | Конец этого объявления |
| `int` | Тип поля `energy`; хранится целое число |
| `energy` | Имя другого поля |
| Последняя `}` | Тело класса закончилось |

Отступы делают вложенность видимой человеку. Java понимает блоки по фигурным скобкам, а не по числу пробелов. Поэтому исчезнувшая скобка — ошибка структуры, а случайно кривой отступ — повод проверить структуру, но сам по себе он не создаёт другой объект.

У `name` и `energy` здесь нет слова `public`, но это не делает их `private`: в этом примере действует доступ внутри пакета. Два класса из нашего учебного файла находятся в одном пакете и могут обращаться к этим полям. Закроем их осознанно на следующей теме; пока открытое чтение нужно для наблюдения.

### Объявили класс — что уже произошло?

Мы описали устройство будущих экземпляров. Мы **ещё не создали ни одного Student**. Существование чертежа дома не означает, что дом построен. Для первого экземпляра в нашей программе понадобится выполнение выражения создания.

## 13. Создание: зачем Student написано два раза

```java
Student anna = new Student();
```

Левая и правая части выполняют разные роли:

| Часть | Вопрос | Ответ |
|---|---|---|
| `Student` слева | Какого типа переменная? | Она предназначена для ссылок, совместимых с Student |
| `anna` | Как к переменной обращаться дальше? | По имени `anna` |
| `=` | Что сохранить в переменной? | Значение выражения справа |
| `new` | Что делаем? | Создаём новый экземпляр |
| `Student()` справа | Какой экземпляр и каким конструктором инициализируем? | Student, здесь конструктором без аргументов |
| `()` | Есть ли переданные аргументы? | Сейчас нет |
| `;` | Где закончилась инструкция? | Здесь |

`Student` слева не является командой «создать студента». Это указание типа. Объект появляется из-за выполнения правой части. Если написать только `Student anna;` внутри метода, мы объявим локальную переменную, но не создадим экземпляр и не зададим ей значение для чтения.

Эквивалентно по смыслу можно разбить действие на две инструкции:

```java
Student anna;
anna = new Student();
```

После второй строки переменная готова к использованию. Если между строками попытаться прочитать `anna`, компилятор сообщит, что локальная переменная могла быть не инициализирована. Это не то же самое, что присвоить ей `null`: `null` — уже определённое значение, но объекта за ним нет.

### Порядок событий

1. Вычисляется выражение `new Student()` справа.
2. Создаётся и инициализируется экземпляр. В нашем простом классе поля сначала получают `null` и 0; собственных присваиваний в конструкторе пока нет.
3. Если создание успешно завершилось, выражение даёт ссылку на экземпляр.
4. Эта ссылка сохраняется в переменной `anna`.

Почему работают скобки, хотя мы не написали конструктор? В обычном классе без объявленных конструкторов компилятор предоставляет конструктор по умолчанию. Подробный разбор этого механизма ты найдёшь в теме 1.2.2.

## 14. Точка, присваивание и кавычки

```java
anna.name = "Анна";
anna.energy = 70;
```

Первую строку читай целиком: «Найди объект по ссылке в `anna`, выбери его поле `name` и присвой этому полю ссылку на строку с текстом “Анна”». Для начала можно говорить короче: «Запиши имя в карточку Анны».

Вторая строка: «У того же объекта сохрани число 70 в поле энергии». `70` без кавычек — целочисленное значение. `"70"` с кавычками — строка. В поле типа `int` строку напрямую присвоить нельзя. Тип нужен именно для того, чтобы такие несовместимые действия обнаруживались.

Точка `.` выбирает член объекта, здесь поле или метод. Это не десятичная точка и не обозначение вложенного файла. Чтобы прочитать `anna.energy`, объект за ссылкой должен существовать. Если `anna == null`, попытка такого доступа к экземплярному полю завершится `NullPointerException`.

### Почему присваивание не означает математическое равенство

`anna.energy = 70` выполняет действие — записывает новое значение. `anna.energy == 70` вычисляет ответ `true` или `false`, не меняя поле. Поэтому одна и две черты равенства не взаимозаменяемы.

Имена и строки тоже различаются: `anna.name = name;` предполагает, что существует доступная переменная `name`; `anna.name = "name";` присваивает буквальный текст «name».

## 15. Метод study: разбираем вообще каждую строку

```java
void study() {
    if (energy < 10) {
        System.out.println(name + ": сначала нужен отдых");
        return;
    }
    energy -= 10;
    System.out.println(name + " учится. Энергия: " + energy);
}
```

### Заголовок void study()

`void` — метод не возвращает вызывающему коду значение. Он при этом может выполнять действия: менять поле и печатать текст. `study` — выбранное имя действия. Пустые `()` означают, что явных аргументов при вызове здесь нет. Однако объект-получатель у экземплярного вызова есть: в `anna.study()` это объект по ссылке `anna`.

Отсутствие аргументов не означает отсутствие данных. Метод использует поля своего текущего объекта. Открывающая `{` начинает тело метода. Последняя `}` заканчивает его. Внутренние скобки относятся к `if`, а не закрывают весь класс.

### Условие if (energy < 10)

`if` означает «выполни следующий блок, если условие истинно». В круглых скобках должно получиться `boolean`: `true` или `false`. Знак `<` проверяет строгое неравенство.

Если энергия 9, выражение `9 < 10` истинно: заходим в блок отказа. Если 10, выражение `10 < 10` ложно: отказ пропускается. Значит, ровно десяти единиц достаточно для занятия. Если по ошибке написать `<=`, студент с энергией 10 тоже получит отказ — изменится правило программы.

### Вывод сообщения

В `System.out.println(...)` имя `System` обозначает стандартный класс, его статическое поле `out` даёт поток вывода, а `println` — метод этого потока. Круглые скобки содержат значение для вывода. После текста добавляется перевод строки.

Знаки `+` в этом выражении соединяют текст. `name + " учится. Энергия: " + energy` собирает строковое представление сообщения. Например, имя «Анна» и число 60 дадут «Анна учится. Энергия: 60». Сам вывод **не уменьшает энергию** — за это отвечает отдельная инструкция перед ним.

Не надо сейчас заучивать внутреннее устройство потока. Важно понимать цепочку обращения и не принимать `System.out.println` за одно волшебное слово.

### return; внутри void

`return;` немедленно завершает **текущий вызов метода**. В нашем случае после сообщения об отказе выполнение возвращается в `main` к строке после `anna.study()` или `boris.study()`.

`return;` не завершает всю программу и не закрывает все методы. Он также не «возвращает ноль»: у `void` нет результата-значения.

Если убрать `return;`, студент с энергией 9 сначала услышит, что нужен отдых, а затем программа всё равно выполнит списание и получит −1. Условие лишь выбирает блок; именно выход не позволяет продолжить неудачное занятие.

### energy -= 10

Для нашего поля `int` и этого выражения смысл такой же, как `energy = energy - 10`: прочитать прежнее значение, вычесть десять, сохранить результат в то же поле. Если было 70, станет 60.

Если написать `energy - 10` без присваивания, это не инструкция изменения поля и такой отдельный оператор Java здесь не допускает. Если вычислить `int remaining = energy - 10`, появится локальная переменная `remaining`, но поле само не изменится. Нужна запись в поле.

### Два пути исполнения

| Исходная энергия | Условие `< 10` | Действия | Энергия после вызова |
|---:|---|---|---:|
| 9 | `true` | Сообщение об отдыхе → `return` | 9 |
| 10 | `false` | Вычесть 10 → сообщение об учёбе | 0 |
| 70 | `false` | Вычесть 10 → сообщение об учёбе | 60 |

Именно исходная энергия конкретного получателя определяет путь, а не то, в каком месте файла написан метод.

## 16. Почему у метода нет static и кто такой this

```java
anna.study();
boris.study();
```

Код `study` объявлен один раз в классе. Но у первого вызова получатель — Анна, у второго — Борис. Не нужно представлять, будто в каждую карточку копируется полный текст метода. Меняется текущий экземпляр, с которым работает вызов.

Внутри нашего метода запись `energy` без затеняющей локальной переменной означает поле текущего экземпляра. Для наглядности можно написать `this.energy`. `this` не является строкой с именем студента и не является ссылкой на класс. Это ссылка на объект, для которого идёт данный экземплярный вызов.

Если метод `study` сделать `static`, текущего экземпляра у него не будет. Чью энергию тогда читать по голому имени `energy`? Компилятор не может выбрать Анну или Бориса вместо программиста. Исправление — оставить метод экземплярным и вызвать его у нужного объекта, а не делать личные поля статическими.

`main` остаётся статическим и всё равно работает с объектами: `anna.study()` явно указывает получателя. Значит, правило не «из static нельзя вызвать обычный метод», а «нельзя неявно использовать отсутствующий текущий объект». Укажи объект — вызов допустим.

## 17. Методы rest и isTired: действия и ответы

```java
void rest() {
    energy += 20;
    if (energy > 100) {
        energy = 100;
    }
}
```

`energy += 20` увеличивает энергию текущего объекта на двадцать. Затем проверка ограничивает результат сверху. При исходных 70 получится 90. При 95 сначала получится 115, затем условие `115 > 100` сработает и в поле запишется 100. В этой учебной модели максимум — 100.

Ограничение выполняется **после** прибавления, потому что проверяем полученное состояние. Если сначала проверить только исходные 95 и затем прибавить 20, можно случайно оставить 115. Порядок инструкций — часть алгоритма.

У `rest` нет вывода: отсутствие новой строки в консоли не означает, что он не выполнился. Изменённое состояние можно прочитать отдельно: `System.out.println(anna.energy);`.

```java
boolean isTired() {
    return energy < 30;
}
```

Перед именем стоит `boolean`: результат обязан быть логическим значением. `energy < 30` уже вычисляет `true` или `false`; `return` передаёт этот ответ вызывающему коду. При энергии 29 результат `true`, при 30 — `false`. Проверка сама не уменьшает энергию.

Можно использовать ответ напрямую:

```java
if (anna.isTired()) {
    anna.rest();
}
```

Сначала вызывается `isTired`, затем полученный `boolean` определяет вход в блок. Скобки `()` после имени означают вызов; запись `anna.isTired` не является чтением существующего поля и не заменяет вызов метода.

## 18. main: прочитать заголовок и понять границы файла

```java
public class ObjectsDemo {
    public static void main(String[] args) {
    }
}
```

| Часть | Что нужно понять сейчас |
|---|---|
| `public` перед классом | Класс объявлен публичным; в нашей файловой форме имя файла — `ObjectsDemo.java` |
| `class ObjectsDemo` | Класс запуска сценария; это другой класс, не Student |
| `public` перед main | Метод доступен для принятой здесь формы точки входа |
| `static` | Для запуска этого main не нужен заранее созданный ObjectsDemo |
| `void` | main не возвращает значение вызывающему коду |
| `main` | Имя принятой в курсе точки входа |
| `String[]` | Тип массива строк |
| `args` | Имя параметра для аргументов командной строки; это не ввод с клавиатуры через Scanner |
| Круглые скобки | Ограничивают список параметров метода |
| Внутренняя пара `{ }` | Ограничивает тело main |
| Внешняя пара `{ }` | Ограничивает тело ObjectsDemo |

При команде `java ObjectsDemo` запускаем этот класс. Не ищем «самую верхнюю исполняемую строку во всём файле». Объявление `Student` ниже `ObjectsDemo` не означает, что Java создаст студента после завершения main. Объявления описывают структуру, инструкции внутри выполняемых методов задают действия.

В одном файле нашего примера два класса верхнего уровня, но только `ObjectsDemo` публичный. Если сделать ещё и `Student` публичным в этом же файле, компилятор потребует соответствующего файла для него. При разделении на два файла сохраняем `ObjectsDemo.java` и `Student.java` в одном учебном пакете и проекте.

## 19. Полная трассировка: куда делись 70 и 40

В таблице считаем только экземпляры **Student**. Строки и массивы тоже объекты Java, но не входят в этот отдельный счёт. «—» означает, что соответствующей переменной или объекта на этом этапе ещё нет.

| Выполненная инструкция | Энергия объекта Анна | Энергия объекта Борис | Что хранит partner | Экземпляров Student | Что попало в консоль |
|---|---:|---:|---|---:|---|
| `Student anna = new Student();` | 0 | — | — | 1 | Ничего |
| `anna.name = "Анна";` | 0 | — | — | 1 | Ничего |
| `anna.energy = 70;` | 70 | — | — | 1 | Ничего |
| `Student boris = new Student();` | 70 | 0 | — | 2 | Ничего |
| `boris.name = "Борис";` | 70 | 0 | — | 2 | Ничего |
| `boris.energy = 40;` | 70 | 40 | — | 2 | Ничего |
| `anna.study();` | 60 | 40 | — | 2 | Анна учится. Энергия: 60 |
| `Student partner = anna;` | 60 | 40 | Ссылку на Анну | 2 | Ничего |
| `partner.rest();` | 80 | 40 | Ссылку на Анну | 2 | Ничего |
| `println(anna.energy)` | 80 | 40 | Ссылку на Анну | 2 | 80 |
| `println(boris.energy)` | 80 | 40 | Ссылку на Анну | 2 | 40 |
| `println(anna == partner)` | 80 | 40 | Ссылку на Анну | 2 | true |
| Создали и заполнили group | 80 | 40 | Ссылку на Анну | 2 | Ничего |
| Первый проход цикла: `group[0].study()` | 70 | 40 | Ссылку на Анну | 2 | Анна учится. Энергия: 70 |
| Второй проход: `group[1].study()` | 70 | 30 | Ссылку на Анну | 2 | Борис учится. Энергия: 30 |
| `println(boris.isTired())` | 70 | 30 | Ссылку на Анну | 2 | false |

Сокращение `println(...)` в таблице означает тот же `System.out.println(...)` в исходнике. Это обозначение для таблицы, а не новый готовый метод, который нужно вставить в программу.

Почему последний ответ `false`, хотя Борис уже потратил энергию? Правило усталости — строго меньше 30. У него ровно 30. Бытовое ощущение «уже устал» не заменяет условие, записанное в коде.

Почему у partner нет отдельной колонки энергии? Это переменная-ссылка на Анну. У одного объекта одно поле `energy`, даже если к нему ведут несколько переменных.

## 20. Вызов метода внутри метода: сначала разобрать выражение

```java
System.out.println(boris.isTired());
```

Не исполняем запись механически слева направо как набор независимых действий. Сначала нужно получить аргумент для `println`:

1. По `boris` находим объект Бориса.
2. Вызываем его `isTired()`.
3. Внутри метода читаем 30 и вычисляем `30 < 30` → `false`.
4. `return` передаёт `false` в место вызова.
5. `println` получает уже вычисленное значение и печатает `false`.

Для понимания можно временно развернуть:

```java
boolean tired = boris.isTired();
System.out.println(tired);
```

Результат тот же. Добавилась только локальная переменная с понятным именем. Это хороший способ разбирать вложенные вызовы, пока они непривычны.

## 21. Массив и цикл: каждое звено цепочки

```java
Student[] group = new Student[2];
group[0] = anna;
group[1] = boris;
for (int index = 0; index < group.length; index++) {
    group[index].study();
}
```

`Student[]` слева — тип «массив ссылок на Student». `group` — имя ссылочной переменной для самого массива. `new Student[2]` создаёт массив длины 2. Число в квадратных скобках — длина массива, а не аргумент конструктора Student.

Сразу после создания: `group[0] == null`, `group[1] == null`. Две следующие инструкции сохраняют ссылки на уже созданных студентов. Сами студенты никуда физически не «переезжают в ячейки»: в ячейках находятся ссылки.

Разбор `for`:

- `int index = 0` — один раз создать счётчик с нулём.
- `index < group.length` — перед каждым проходом проверять допустимость продолжения; `length` массива равен 2.
- `index++` — после тела увеличить счётчик на один.
- Тело — `group[index].study()`.

Внутри тела сначала берётся элемент массива по индексу, затем полученная ссылка используется как получатель `study`. Это два последовательных поиска: переменная → массив → конкретный Student. При `index = 0` получатель Анна; при 1 — Борис. После увеличения до 2 условие `2 < 2` ложно: третьего вызова нет.

Если заменить `<` на `<=`, цикл попробует обратиться к `group[2]`. Это выход за границы массива, а не создание третьего студента. Если забыть заполнить `group[1]`, границы будут допустимы, но вызов у `null` завершится `NullPointerException`. Это две разные ошибки с разными причинами.

## 22. Объект как аргумент: теперь полностью, а не намёком

В класс запуска, рядом с main и снаружи его тела, можно добавить:

```java
static void help(Student learner) {
    learner.rest();
}
```

Вызов из main: `help(anna);`.

`Student` — тип параметра; `learner` — его локальное имя. При вызове в параметр копируется значение ссылки из `anna`. Затем `learner.rest()` вызывает отдых того же объекта. Поэтому энергия Анны увеличивается, хотя имя `anna` внутри `help` вообще не используется.

`static` нужен здесь для прямого вызова из статического main в классе запуска. Метод не имеет собственного текущего Student: он получает нужного студента явным параметром. `rest`, напротив, — экземплярный метод Student, которому нужен получатель.

Если внутри help выполнить `learner = new Student()`, изменится только параметр. Переменная `anna` у вызывающего кода всё ещё ведёт к старому экземпляру. Чтобы заменить её значение, нужно явно получить новую ссылку и присвоить её снаружи.

Пример `help` — дополнительный опыт. Вставка его вызова в исходный ObjectsDemo изменит дальнейшие значения энергии и ожидаемый вывод. Проверяй его отдельно или составь новую трассировку; не сравнивай изменённую программу со старым ответом.

## 23. Ошибка → причина → исправление

| Что написали или увидели | Что произошло | Как проверить и исправить |
|---|---|---|
| `Student anna; anna.study();` | Локальная ссылка ещё не получила значения | Создать объект и присвоить ссылку до обращения |
| `Student anna = null; anna.study();` | Значение есть, но объекта за ним нет | Найти пропущенное создание; не подменять его бессмысленной проверкой |
| `Student.study();` при обычном study | Не указан объект для экземплярного действия | Вызвать `anna.study()` у нужного экземпляра |
| `anna.energy = "70";` | Полю int предложили строку | Для этого примера использовать целое `70` без кавычек |
| `int result = anna.study();` | Метод void не даёт значения для присваивания | Вызвать действие отдельно; для ответа нужен метод с типом результата |
| `anna.study;` | Нет корректного вызова метода | Написать `anna.study();` |
| После `rest()` ничего не напечаталось | В методе нет вывода, но поле изменилось | Отдельно прочитать энергию, не объявлять метод неработающим |
| После `partner = anna` отдых виден через anna | Это ожидаемый эффект общей ссылки | Если нужен независимый объект, создать его отдельно и заполнить поля |
| У всех студентов меняется одна энергия | Личное поле ошибочно сделано static | Вернуть экземплярное поле и проверять конкретного получателя |
| `group[2]` при длине 2 | Допустимы только индексы 0 и 1 | Исправить границу цикла |
| `group[1].study()` при null в ячейке | Массив существует, Student в этой ячейке — нет | Заполнить ссылку до вызова или осознанно пропускать пустые ячейки |

Текст сообщения компилятора может различаться между версиями и средами. Важнее уметь назвать причину, чем запомнить английскую строку наизусть.

## 24. От образца к собственной программе: мостик без прыжка

Задача — телефон с моделью и зарядом. Здесь нужно перенести уже знакомую структуру, а не угадывать неизвестный способ решения.

### Шаг А. Сопоставить смысл

| Было Student | Станет Phone | Что сохраняется |
|---|---|---|
| `String name` | `String model` | Текстовое поле |
| `int energy` | `int battery` | Числовое поле состояния |
| `study()` | `use()` | Проверка и уменьшение на 10 |
| `rest()` | `charge()` | Увеличение на 20 с ограничением 100 |
| `isTired()` | `isLow()` | Логический ответ; здесь порог 20 |

Не менять сразу всё. Сначала объявить новый класс с двумя полями и добиться компиляции. Затем создать один объект и вывести его поля. Только после этого добавлять действия.

### Шаг Б. Первый запуск без методов

В своём классе запуска создать `Phone firstPhone = new Phone();`, присвоить `model = "Учебный телефон"`, `battery = 70`, вывести значения. Чтобы это заработало, объявление класса Phone с обоими полями уже должно находиться в проекте. Конструктор с параметрами на этой теме ещё не требуется.

### Шаг В. Один метод, одна проверка

Написать `void use()` по образцу `study`. До вызова батарея 70, после одного вызова 60. Затем проверить исходные 9 и 10: при 9 должен быть отказ без изменения; при 10 — заряд 0. Пока это не работает, не добавлять новые методы.

### Шаг Г. Отдых превращается в зарядку

Написать `charge()` по образцу `rest`. Проверить 70 → 90 и 95 → 100. Написать `isLow()` с порогом 20. Сравнить 19 → true и 20 → false. Здесь намеренно другие пороги: это проверяет понимание, а не точное копирование.

### Шаг Д. Второй объект и вторая ссылка — по отдельности

Создать второй Phone со своим зарядом 40. Вызов `firstPhone.use()` не должен менять второй телефон. Затем выполнить `Phone backup = firstPhone;` и вызвать `backup.charge()`: изменение должно быть видно через firstPhone. Объяснить оба результата стрелками.

Не добавлять сюда конструкторы с параметрами, наследование, коллекции, Scanner или меню, пока не понятна основная модель. Они не являются условием выполнения этой задачи.

### Что считать доказательством понимания

Ты можешь показать две разные карточки объектов; назвать, у какой изменится поле; объяснить каждую часть вызова; предсказать результат без запуска; затем подтвердить его программой. Просто наличие похожего кода в редакторе этого ещё не доказывает.
