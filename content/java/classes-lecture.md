# 1.2.1 Классы и объекты

## Основные понятия



> **Класс** — описание типа объектов: какие данные они хранят и какие действия доступны для них.

>

> **Объект** — конкретный экземпляр класса со своим состоянием. У одного класса может быть много объектов.

>

> **Поле объекта** — переменная, принадлежащая конкретному объекту и хранящая часть его состояния.

>

> **Метод объекта** — действие, вызываемое для конкретного объекта и способное работать с его состоянием.

>

> **`this`** — ссылка на текущий объект внутри его экземплярного метода или конструктора.

>

> **Инкапсуляция** — объединение данных и поведения в классе и управление доступом к состоянию через выбранный интерфейс.



## 1. Зачем класс, если уже есть переменные

«У одного персонажа игры есть имя и энергия. Пока он один, напишем две переменные. Но если персонажей двадцать, отдельно хранить имена и энергию опасно: легко перепутать, кому принадлежит число. Нам нужна карточка, в которой связанные данные находятся вместе».

На доске написать `annaName`, `annaEnergy`, `borisName`, `borisEnergy`. Спросить, как добавить ещё сто студентов. Два параллельных массива возможны, но программист должен постоянно следить, чтобы одинаковые индексы означали одного человека. Класс выражает эту связь напрямую.

Пустой шаблон карточки — класс. Заполненная карточка Анны — объект. Заполненная карточка Бориса — другой объект. Сам шаблон не является ни Анной, ни Борисом. У аналогии есть ограничение: программный объект содержит ещё и доступное поведение, а не только подписи в анкете.

## 2. Сначала самый маленький класс

```java
class Student {
    String name;
    int energy;
}
```

Разобрать каждую часть: `class` начинает описание, `Student` — выбранное имя нового типа, скобки ограничивают тело класса, поля объявляются внутри класса, но вне методов. Большая буква в имени класса — соглашение об именовании. `Student` — тип, как `String`, а `anna` будет именем переменной.

Описание класса ещё не создаёт объекты `Student`. Пустая форма карточки может существовать даже до того, как мы заполнили первую карточку.

## 3. Четыре действия, спрятанные в одной строке

```java
Student anna = new Student();
```

Разделить цветами: `Student` — какой тип ссылки допустим; `anna` — имя переменной; `new Student()` — выражение создания объекта; `=` — сохранить полученную ссылку.

Сначала выражение справа создаёт и инициализирует объект, затем полученная ссылка присваивается переменной слева. Переменная не содержит «всего студента внутри себя». Она позволяет найти объект.

В этом минимальном классе конструкторы не написаны, поэтому Java предоставляет конструктор по умолчанию. Подробно разберём на следующей теме; пока не приписываем скобкам магию «вызова класса как обычного метода».

```java
anna.name = "Анна";
anna.energy = 70;
Student boris = new Student();
boris.name = "Борис";
boris.energy = 40;
```

Точка читается «у этого объекта». `anna.energy` — энергия объекта, к которому ведёт `anna`. `boris.energy` — энергия другого объекта. Две записи `new Student()` создали два объекта с независимыми экземплярными полями.

«Изменили `anna.energy`. Должен ли измениться Борис?» Нет: это другой объект. «Всегда ли две переменные означают два объекта?» Нет: повторить предыдущую тему про ссылки.

## 4. Поля и локальные переменные

Поля `String name` и `int energy` получают начальные значения `null` и 0 до наших присваиваний. Это не означает, что Java автоматически дала студенту осмысленное имя или допустимое состояние.

Локальная переменная в методе не получает такого автоматического разрешения на чтение: `int energy; System.out.println(energy);` не скомпилируется. Одно и то же имя типа не делает поля и локальные переменные одинаковыми по правилам инициализации.

Создать студента и до заполнения прочитать два поля: ожидаются `null` и 0. Затем заполнить и сравнить. Не вызывать метод у `name`, пока там `null`.

## 5. Метод: действие, у которого есть хозяин

Добавляем в тело `Student`:

```java
void study() {
    if (energy < 10) {
        System.out.println(name + ": сначала нужен отдых");
        return;
    }
    energy -= 10;
    System.out.println(name + " учится. Энергия: " + energy);
}
```

«Текст метода написан один раз, но состояние зависит от получателя вызова». В `anna.study()` текущий объект — Анна. В `boris.study()` — Борис. Внутри `study` короткая запись `energy` обращается к полю текущего объекта; можно явно написать `this.energy`.

Здесь нет `static`: методу важно, **кто именно** учится. Не нужно копировать тело метода для каждой карточки. Метод описан классом, а работает с конкретным получателем вызова.

Разобрать построчно: условие проверяет возможность занятия; `return;` завершает вызов без результата; `energy -= 10` меняет поле; вывод показывает новое состояние. Если энергии ровно 10, занятие допустимо, результат — 0. Если 9 — состояние сохраняется.

Далее добавить `rest()`: увеличить энергию на 20, но не выше 100; и `isTired()`: вернуть результат `energy < 30`. У `isTired` результат `boolean`, его удобно использовать прямо в `if`.

## 6. Где находится main и как запустить

В полном примере ниже `ObjectsDemo` — публичный класс запуска, `Student` — второй класс в том же файле без `public`. Имя файла — `ObjectsDemo.java`. Это удобная учебная упаковка; обычно каждый класс размещают в своём файле.

Пока используем знакомую форму `public static void main(String[] args)`. `main` — место запуска сценария, а `Student` — описание участников сценария. Из `main` вызываем `anna.study()`, а не просто `study()`: нужен конкретный объект.

Вложенные рамки: файл → два соседних класса; внутри `Student` — поля и методы; внутри `ObjectsDemo` — `main`. Не вкладывать объявление `Student` внутрь `main` для этой работы.

## 7. Вторая пара: один объект, две ссылки

```java
Student partner = anna;
partner.rest();
```

Нового студента нет: выполнено присваивание ссылки. Через `partner` вызван метод того же объекта Анны. Теперь `anna.energy` показывает изменённую энергию. Это тот же сюжет, что с массивом, только объект теперь имеет собственный класс.

```java
Student another = new Student();
another.name = "Анна";
another.energy = anna.energy;
```

Здесь другой объект, хотя данные могут совпадать. «Одинаковые данные» и «тот же экземпляр» — разные вопросы. `anna == partner` даст `true`; `anna == another` — `false`. У нашего класса `equals` пока не переопределён, поэтому не ждём от него сравнения всех полей.

## 8. Передаём студента в метод

Метод `help(Student learner)` может вызвать `learner.rest()`: изменится тот же объект, который передан при вызове. Но `learner = new Student()` переназначил бы только параметр. Тип `Student` не отменяет правил ссылок из предыдущего урока.

Пусть Анна имеет энергию 20, Борис — 40. Вызвать `help(anna)`. Предсказать энергии обоих до запуска. Ожидаются 40 и 40. Совпавшие числа не означают, что объекты слились.

## 9. Массив студентов: полки сначала пусты

```java
Student[] group = new Student[2];
group[0] = anna;
group[1] = boris;
```

Первая строка создаёт один массив из двух ссылочных ячеек, первоначально `null`. Она не создаёт двух студентов. Следующие строки помещают ссылки на уже существующие объекты. Изменение через `group[0]` видно через `anna`.

В итоговом примере для каждого элемента вызывается `study()`. В реальной работе при частично заполненном массиве сначала проверять `group[index] != null`. Здесь оба элемента явно заполнены.

## 10. Зачем закрывать поля

Открытые для пакета поля пока упрощают первый эксперимент. Но запись `anna.energy = -500` обходит правило про отдых и учёбу. На следующем уроке сделаем поля `private` и зададим безопасное создание через конструктор.

Инкапсуляция не сводится к автоматической генерации геттеров и сеттеров для всего. Важнее решить, какие действия вообще разрешены: для энергии могут быть лучше `study` и `rest`, чем возможность произвольно устанавливать любое число.

Наследование, полиморфизм и абстракцию сейчас только назвать будущими инструментами. Не требовать заучивания четырёх терминов вместо понимания одного работающего объекта.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 ObjectsDemo.java`, затем `java ObjectsDemo`. JDK 17 или новее.

```java
public class ObjectsDemo {
    public static void main(String[] args) {
        Student anna = new Student();
        anna.name = "Анна";
        anna.energy = 70;
        Student boris = new Student();
        boris.name = "Борис";
        boris.energy = 40;
        anna.study();
        Student partner = anna;
        partner.rest();
        System.out.println(anna.energy);
        System.out.println(boris.energy);
        System.out.println(anna == partner);
        Student[] group = new Student[2];
        group[0] = anna;
        group[1] = boris;
        for (int index = 0; index < group.length; index++) {
            group[index].study();
        }
        System.out.println(boris.isTired());
    }
}
class Student {
    String name;
    int energy;
    void study() {
        if (energy < 10) {
            System.out.println(name + ": сначала нужен отдых");
            return;
        }
        energy -= 10;
        System.out.println(name + " учится. Энергия: " + energy);
    }
    void rest() {
        energy += 20;
        if (energy > 100) {
            energy = 100;
        }
    }
    boolean isTired() {
        return energy < 30;
    }
}
```

Ожидаемый вывод:

```text
Анна учится. Энергия: 60
80
40
true
Анна учится. Энергия: 70
Борис учится. Энергия: 30
false
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.
