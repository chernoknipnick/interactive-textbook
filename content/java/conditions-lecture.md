# Условный оператор: if, if-else, switch-case

> Тема 1.1.3 по программе. Опирается на операции сравнения (`==`, `>`, `<` и т.д.) и логические операции (`&&`, `||`, `!`), разобранные в [[1 Типы данных и операции|лекции 1.1.1]] — там мы только вычисляли `boolean`-значения и печатали их, здесь научимся по ним принимать решения: выполнять один блок кода вместо другого. Как и в [[0.5 Первая программа на Java структура и запуск|лекции 0.5]], каждая новая конструкция и каждое новое слово разобраны отдельно.

## 1. Зачем это нужно — ветвление

До сих пор все наши программы (в том числе лабораторная работа 1) выполнялись строго сверху вниз, строка за строкой, без исключений. Реальные программы почти никогда так не работают: банковское приложение по-разному реагирует на достаточный и недостаточный баланс, игра по-разному обрабатывает победу и поражение, форма регистрации по-разному отвечает на верный и неверный пароль. Механизм, который позволяет программе идти по разным путям в зависимости от условия, называется **ветвлением** (branching). В Java для этого есть три инструмента: `if`, `if-else` (и цепочка `else if`) и `switch-case`. Разберём все три — и каждое новое слово, которое при этом появляется.

## 2. `if` — выполнить, только если условие истинно

```java
if (условие) {
    // код, который выполнится, только если условие == true
}
```

### Разбор конструкции `if`

- **`if`** — ключевое слово Java, зарезервированное именно под эту конструкцию: написать `if` как имя переменной или метода нельзя, компилятор его не позволит использовать ни для чего другого.
- **`(условие)`** — круглые скобки здесь обязательны, и внутри них может быть **любое** выражение типа `boolean`: одиночная переменная (`if (isReady)`), сравнение (`if (a > 5)`), сложное логическое выражение (`if (a > 5 && b != null)`) — те самые операции, что разбирались в лекции 1.1.1. Если выражение в скобках не `boolean`, а, например, `int`, код не скомпилируется — в отличие от некоторых языков (C, JavaScript), где число само по себе может считаться «истинным» или «ложным», в Java такого нет: в `if` может стоять только настоящий `boolean`.
- **`{` и `}`** — фигурные скобки образуют **тело** — блок кода, который относится к `if`. Технически, если тело состоит ровно из одной инструкции, скобки можно опустить (`if (a < 10) System.out.println("мало");`) — но делать так не стоит: см. раздел про «висячий else» в конце лекции, где отсутствие скобок — прямая причина одной из самых незаметных ошибок.

Важно то, чего в этой конструкции **нет**: нет варианта «а если условие ложно, сделай что-то другое» — если `условие` равно `false`, программа просто пропускает всё тело `if` целиком и идёт к коду, который следует дальше.

### Условием может быть не только сравнение, но и вызов метода

В скобках `if (...)` не обязательно писать сравнение или логическую операцию напрямую — подойдёт **любое** выражение, результат которого — `boolean`, в том числе вызов метода, если у него объявлен возвращаемый тип `boolean`:

```java
public class PasswordCheck {
    public static void main(String[] args) {
        String password = "qwerty123";

        if (isStrong(password)) {
            System.out.println("Пароль надёжный");
        } else {
            System.out.println("Пароль слишком простой — минимум 8 символов");
        }
    }

    static boolean isStrong(String password) {
        return password.length() >= 8;
    }
}
```

Здесь `isStrong(password)` — вызов обычного метода, устроенного точно как `main` из лекции 0.5 (`static`, есть тело, есть параметр), только вместо `void` у него тип возврата `boolean`, а вместо пустого тела — `return` с выражением. Java сначала полностью выполняет метод `isStrong`, получает от него `true` или `false` через `return`, и только после этого подставляет это значение в `if` — с точки зрения `if` нет никакой разницы, откуда взялся `boolean`: из прямого сравнения (`percent < 10`), из переменной (`isReady`) или из результата вызова метода (`isStrong(password)`). Это особенно удобно, когда проверка сложная и не умещается в одну строку: вместо того чтобы писать длинное условие прямо внутри `if (...)`, его можно вынести в отдельный метод с понятным именем — тогда сам `if (isStrong(password))` читается почти как обычное предложение на русском.

```java
import java.util.Scanner;

public class BatteryCheck {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Сколько процентов заряда осталось? ");
        int percent = scanner.nextInt();

        if (percent < 10) {
            System.out.println("Осталось меньше 10% — подключите зарядку");
        }
        System.out.println("Проверка завершена");
    }
}
```

Если ввести `5` — выведутся обе строки. Если ввести `50` — только «Проверка завершена»: блок `if` был пропущен целиком, а не выполнен «наполовину».

### Что здесь новое: `Scanner` — чтение ввода с клавиатуры

- **`import java.util.Scanner;`** — строка в самом верху файла, **до** объявления класса. `import` подключает к вашему файлу класс, который лежит не «под рукой» (как `System`, который доступен всегда), а в другом пакете стандартной библиотеки Java — здесь это `java.util.Scanner`. Без этой строки компилятор не поймёт, что такое `Scanner`, и выдаст ошибку `cannot find symbol`.
- **`Scanner scanner = new Scanner(System.in);`** — здесь `Scanner` встречается дважды с разным смыслом: первое — это **тип** переменной (слева), второе, после `new`, — вызов **конструктора**, который создаёт сам объект. `new` — ключевое слово, означающее «создать новый объект в памяти»; про конструкторы подробно будет отдельная лекция (1.2.2), пока просто запомните: чтобы начать пользоваться `Scanner`, его сначала нужно создать через `new Scanner(...)`, в отличие от `System.out`, который уже готов к использованию.
- **`System.in`** — «стандартный поток ввода»: то, что вводит пользователь с клавиатуры (или в онлайн-компиляторе — специальное поле для ввода рядом с окном вывода). Это пара к уже знакомому `System.out` из лекции 0.5: `System.out` — данные наружу (на экран), `System.in` — данные внутрь (от пользователя).
- **`scanner.nextInt();`** — метод объекта `scanner`, который **ждёт**, пока пользователь введёт целое число и нажмёт Enter, а затем возвращает это число как `int`. Если пользователь введёт не число (например, слово), программа «упадёт» с ошибкой `InputMismatchException` — то же самое семейство проблем, что и `Integer.parseInt()` на нечисловой строке из лабораторной работы 1 (см. [[0.5 Первая программа на Java структура и запуск|лекцию 0.5]]).

Частый практический случай — «защититься» от плохих данных и ничего не делать, если они плохие:

```java
static void printLength(String text) {
    if (text != null) {
        System.out.println("Длина строки: " + text.length());
    }
}
```

Без этой проверки `text.length()` на `null`-значении «уронит» программу с ошибкой `NullPointerException` — вызвать метод `.length()` у того, чего не существует, невозможно. `if (text != null)` — это защита, которая отсекает такой вызов заранее.

## 3. `if-else` — ровно один из двух вариантов

Если нужно не «сделать или ничего не делать», а «сделать одно ИЛИ сделать другое» — добавляется `else`:

```java
if (percent < 10) {
    System.out.println("Осталось меньше 10% — подключите зарядку");
} else {
    System.out.println("Заряда достаточно");
}
```

### Разбор конструкции `else`

- **`else`** — ключевое слово, которое **не может существовать само по себе**: оно всегда идёт сразу после закрывающей `}` какого-то `if` и не имеет собственных скобок с условием — у `else` нет своего «если», он подхватывает всё, что не подошло под условие `if` перед ним.
- Синтаксически `else` необязателен (можно писать просто `if` без него, как в разделе 2) — но если он есть, у него должно быть тело в `{ }`, как и у `if`.
- Важное следствие: `if-else` вместе гарантируют, что выполнится **ровно одна** из двух веток, никогда не обе и никогда ни одной. Это отличает `if-else` от двух отдельных `if` подряд (`if (a < 10) {...} if (a >= 10) {...}`), где формально можно было бы получить тот же результат, но программа при этом дважды проверяла бы условие — и это не то же самое, если условие между проверками успело измениться (например, если внутри первого `if` меняется переменная `a`).

### Цепочка `else if` — больше двух вариантов

Когда вариантов больше двух, `else`-блок сам может содержать ещё один `if` — так получается цепочка:

```java
if (percent <= 0 || percent > 100) {
    System.out.println("Некорректное значение");
} else if (percent < 10) {
    System.out.println("Критически низкий заряд");
} else if (percent < 30) {
    System.out.println("Пора зарядить");
} else {
    System.out.println("Заряда достаточно");
}
```

**Важно понимать: `else if` — это не новое ключевое слово и не отдельная конструкция.** Формально это просто `else`, тело которого — ещё один `if`:

```java
if (percent <= 0 || percent > 100) {
    System.out.println("Некорректное значение");
} else {
    if (percent < 10) {
        System.out.println("Критически низкий заряд");
    } else {
        if (percent < 30) {
            System.out.println("Пора зарядить");
        } else {
            System.out.println("Заряда достаточно");
        }
    }
}
```

Это ровно тот же код, что и версия с `else if` выше — просто с явными вложенными скобками. `else if` — это просто общепринятый способ писать такую конструкцию без «лесенки» из отступов, чтобы код оставался читаемым, когда веток пять или десять.

Ключевое правило, которое часто путают: условия проверяются **по порядку сверху вниз**, и как только находится первое истинное — выполняется только его блок, а все остальные проверки дальше по цепочке пропускаются, даже если формально им бы тоже соответствовали. Например, при `percent = 5` условие `percent < 10` истинно и `percent < 30` тоже было бы истинно — но до второй проверки дело уже не доходит, программа напечатает только «Критически низкий заряд» и выйдет из всей цепочки.

## 4. `switch-case` — сравнение одной переменной со многими значениями

Когда вариантов много и все они сравнивают **одну и ту же** переменную с конкретными значениями (а не разные условия друг с другом), длинная цепочка `else if` становится трудно читаемой. Для этого случая есть `switch`:

```java
import java.time.DayOfWeek;
import java.time.LocalDate;

public class DayChecker {
    public static void main(String[] args) {
        DayOfWeek today = LocalDate.now().getDayOfWeek();

        switch (today) {
            case SATURDAY:
            case SUNDAY:
                System.out.println("Сегодня выходной");
                break;
            case FRIDAY:
                System.out.println("Сегодня пятница — почти выходной");
                break;
            default:
                System.out.println("Сегодня рабочий день");
                break;
        }
    }
}
```

### Что здесь новое: как узнать сегодняшний день

- **`import java.time.DayOfWeek;`** и **`import java.time.LocalDate;`** — два отдельных `import`: `LocalDate` умеет работать с датами, `DayOfWeek` — специальный тип-перечисление (`enum`, о нём подробно будет тема 1.2.7), который может принимать только одно из семи строго определённых значений: `MONDAY`, `TUESDAY`, ..., `SUNDAY`, и никакое другое.
- **`LocalDate.now()`** — статический метод (как `String.valueOf(...)` из лекции 0.5), возвращающий объект с сегодняшней датой — вызывается через имя класса `LocalDate`, а не через `new`, потому что для «текущей даты» не нужно ничего создавать вручную, она и так одна.
- **`.getDayOfWeek()`** — метод уже полученного объекта даты, возвращающий именно день недели как значение типа `DayOfWeek`.

### Разбор конструкции `switch`

- **`switch (today)`** — `switch` — ключевое слово, за которым в круглых скобках стоит переменная, которую сравниваем. `switch` умеет работать с `byte`, `short`, `int`, `char`, `String` и `enum` (как `DayOfWeek` здесь) — но не с `boolean` и не с `double`/`float`: сравнивать дробные числа на точное равенство вообще плохая идея (из-за особенностей хранения чисел с плавающей точкой в памяти), поэтому язык такую возможность даже не даёт.
- **`case SATURDAY:`** — `case` — ключевое слово, за которым следует конкретное значение (не выражение, не диапазон — только точное значение) и двоеточие `:`. Если значение в `switch (...)` равно значению после `case`, выполнение начинается именно с этой строки.
- **`break;`** — самая важная и самая часто забываемая деталь. Без `break` выполнение не останавливается на конце своего `case`, а «проваливается» (fall-through) в следующий `case` подряд, даже если его условие не совпало. Ровно на этом эффекте основан приём выше: `case SATURDAY:` идёт без `break` сразу перед `case SUNDAY:` — значит, оба дня выполняют один и тот же код «Сегодня выходной». Но если забыть `break` там, где вы не хотели проваливания, программа выполнит гораздо больше кода, чем задумано — это одна из самых частых ошибок логики (не компиляции!) у новичков в `switch`.
- **`default:`** — необязательная ветка «если ничего не подошло», аналог финального `else` в цепочке `if`. Если `default` нет и ни один `case` не совпал — `switch` просто ничего не сделает, программа продолжится дальше.

## 5. `if-else` vs `switch` — когда что выбрать

| | `if / else if` | `switch` |
|---|---|---|
| Разные независимые условия (`x > 5`, `y != null`, `a && b`) | ✅ подходит | ❌ не подходит |
| Одна переменная сравнивается со множеством конкретных значений | можно, но громоздко | ✅ короче и нагляднее |
| Диапазоны (`x < 10`, `10 <= x < 30`, ...) | ✅ единственный вариант | ❌ невозможно |
| Забыли `break` | не актуально | легко получить незаметный fall-through |

## 6. Частые ошибки

- **«Висячий» else, привязанный не к тому `if`.** Если писать `if` без фигурных скобок для однострочного тела, `else` всегда «прилипает» к ближайшему предыдущему `if`, а не к тому, что подразумевал автор кода:

  ```java
  if (a > 0)
      if (b > 0)
          System.out.println("оба положительные");
  else
      System.out.println("это else относится к if (b > 0), а не к if (a > 0)!");
  ```

  Несмотря на отступ, зрительно намекающий на обратное, этот `else` относится именно к `if (b > 0)` — компилятор ориентируется не на отступы, а на то, что `else` всегда привязывается к ближайшему предыдущему `if` без своего `else`. Правило, которое снимает проблему полностью: **всегда** ставить `{ }`, даже для одной строки внутри `if`.
- **`=` вместо `==` в условии.** `if (a = 5)` — это не сравнение, а присваивание; в Java (в отличие от C) такой код в большинстве случаев вообще не скомпилируется, если `a` не типа `boolean`, — и это одна из немногих ошибок, за которую здесь стоит быть благодарным компилятору.
- **Забытый `break` в `switch`.** См. раздел 4 — код скомпилируется и запустится, но выполнит не то, что задумано. Такую ошибку не покажет компилятор, только неправильный результат на экране.
- **Проверка `String` через `==` вместо `.equals()`.** Забегая немного вперёд (полноценно строки разберём отдельно): `if (name == "Иван")` для строк часто работает не так, как ожидается, — правильно `if (name.equals("Иван"))`. Пока просто держите это в голове как исключение из общего правила «сравнение через `==`».

## 7. Итог лекции

Три инструмента ветвления в Java решают одну и ту же задачу — выполнить один код вместо другого — разными способами: `if` подходит, когда нужно либо выполнить блок, либо пропустить его, а условием ему может служить не только прямое сравнение, но и вызов метода с возвращаемым типом `boolean` (`if (isStrong(password))`); `if-else`/`else if` — когда вариантов несколько и они завязаны на независимые условия, проверяемые по порядку сверху вниз до первого истинного (а «`else if`» — это не новая конструкция, а просто `if` внутри `else`); `switch` — когда одна и та же переменная сравнивается с набором конкретных значений, и здесь критично не забывать `break`, иначе выполнение «проваливается» в соседние ветки. По пути встретились и новые инструменты для работы с данными — `Scanner` для чтения ввода с клавиатуры и статические методы `LocalDate`/`DayOfWeek` для работы с датами — оба ещё не раз пригодятся впереди. Вместе с типами и операциями из лекции 1.1.1 это уже полноценный набор, чтобы писать программы с реальной логикой, а не только последовательность команд сверху вниз.

**Проверь себя:**

1. В цепочке `if (percent <= 0 || percent > 100) {...} else if (percent < 10) {...} else if (percent < 30) {...} else {...}` при `percent = 200` какая именно ветка выполнится и почему остальные при этом не проверяются?
2. Почему `switch` нельзя использовать с типом `double`, а `if`/`else if` — можно (например, `if (price < 99.99)`)?
3. В `switch` по дням недели два `case` — `SATURDAY` и `SUNDAY` — идут подряд без `break` между ними и оба ведут к одному и тому же выводу. Что произойдёт, если убрать `break` ещё и после блока `SUNDAY` (то есть между `SUNDAY` и `FRIDAY`)?
4. Метод `printLength` защищён проверкой `if (text != null)`. Что произойдёт при вызове `printLength(null)` — и что бы произошло, если убрать эту проверку?
5. Объясните разницу между `if (a = 5)` и `if (a == 5)`. Почему первое в большинстве случаев Java не даст даже скомпилировать, а не просто выполнит «не то, что хотели»?
