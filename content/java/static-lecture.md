# 1.2.3 Статические поля и методы

## Основные понятия



> **Экземплярное поле** — поле, отдельная переменная которого существует у каждого экземпляра класса.

>

> **Статическое поле (`static`)** — поле класса, не создаваемое заново для каждого экземпляра. В наших примерах у одного загруженного класса одна такая общая переменная.

>

> **Статический метод (`static`)** вызывается без текущего экземпляра. У него нет `this`, но он может работать с объектами, явно полученными или созданными в его коде.

>

> **`final`** запрещает повторное присваивание переменной после её допустимой инициализации. Само по себе это не означает неизменяемости объекта, на который ведёт ссылка.

>

> **`static final`** часто используют для констант класса; например, `static final int MAX_ENERGY = 100`.



## 1. Школьная доска и личные тетради

«У каждого ученика своя тетрадь с оценками. А название школы написано на общей доске. Исправили запись на доске — никто не переписывал отдельные тетради. Нам нужно явно отличать личные данные от общей записи».

Энергия Анны — личная. Энергия Бориса — другая. Общее число успешно созданных объектов этого класса — общая характеристика. Аналогия с доской показывает общность, но не означает автоматическую синхронизацию по сети или между разными запусками программы.

## 2. Самая опасная «починка» прошлого урока

Если сделать `energy` статическим, у студентов не будет отдельных переменных энергии. Изменение через одного студента повлияет на общее значение. Это ошибка модели, даже если программа компилируется.

«Название группы делать static?» Только если по модели все объекты этого класса действительно относятся к одной общей группе. Если студенты из разных групп, поле должно быть экземплярным. `static` выбирают по смыслу, а не потому, что значения сегодня случайно совпали.

Раздели свойства на две категории: имя и энергия принадлежат экземпляру, а общее ограничение энергии и число созданий — классу. При этом число созданий меняется, а ограничение остаётся постоянным. Свойство может быть общим и изменяемым: static не равно final.

## 3. Счётчик созданий

```java
private static int createdCount;
```

Начальное значение статического поля `int` — 0. В основном конструкторе после успешной проверки данных и заполнения полей выполняется `createdCount++`.

Первое успешное создание даёт 1, второе — 2. Присваивание `Student partner = anna` не вызывает конструктор и счётчик не увеличивает. Вызов короткого конструктора через `this(name, 100)` тоже не должен добавлять второе увеличение: увеличиваем в одном основном месте.

Этот счётчик — число успешно завершённых созданий через наши конструкторы в данном запуске и учебном однопоточном сценарии. Он **не** показывает число живых объектов, посетителей сайта, зарегистрированных людей или существующих файлов. Если ссылка потерялась, счётчик не уменьшается. Сборщик мусора не ведёт этот учёт за нас. Для многопоточности обычного `++` недостаточно — это за рамками пары.

## 4. Метод класса: спросить о классе, не выбирая студента

```java
public static int getCreatedCount() {
    return createdCount;
}
```

Вызов: `Student.getCreatedCount()`. Здесь имя класса слева от точки. Не нужно создавать фиктивного студента, чтобы узнать общее число созданий.

Java позволяет многие статические вызовы записывать через ссылочную переменную, но мы так не пишем: `anna.getCreatedCount()` создаёт ложное впечатление, что спрашиваем об Анне. Общий член обозначаем через имя класса.

## 5. Почему в static нет this

В `anna.getEnergy()` получатель известен — Анна. В `Student.getCreatedCount()` никакой конкретный студент не выбран. Слово «этот» не к кому отнести, поэтому `this` недоступно.

Статический метод не может просто написать `return energy;`, если `energy` — экземплярное поле: нужно указать, **чья** энергия. Однако статический метод вполне может принять `Student learner` и вызвать `learner.getEnergy()`. Неверное правило «static никогда не работает с объектами» заменяем точным «static не имеет неявного текущего экземпляра».

В `main` уже были объекты `Scanner`, `Random`, массивы и студенты. Значит, запрета работать с объектами у статических методов никогда не было.

## 6. Метод-проверка, которому нужен только аргумент

```java
public static boolean isValidEnergy(int energy) {
    return energy >= 0 && energy <= MAX_ENERGY;
}
```

Чтобы проверить число 70, не требуется объект с именем и собственным состоянием. Поэтому `Student.isValidEnergy(70)` — разумный метод класса. Он похож на знакомый `Math.max` по форме вызова.

Сначала определи, какие данные требуются методу. Если он использует личную энергию получателя, как study(), ему нужен конкретный объект и он остаётся экземплярным. Не добавляй static только ради удобного вызова из main: так можно потерять связь действия с нужным объектом.

## 7. static и final отвечают на разные вопросы

`static` — общая переменная класса или отдельная у экземпляра? `final` — разрешено ли повторное присваивание этой переменной?

У `MAX_ENERGY` оба признака: одна общая граница, менять её значение нельзя. Имена констант обычно пишут большими буквами с подчёркиваниями.

Таблица четырёх сочетаний: обычное поле — своё и изменяемое; `final` — своё без повторного присваивания; `static` — общее и изменяемое; `static final` — общее без повторного присваивания.

Запись `final int[] values = {1, 2}` запрещает `values = new int[]{3}`, но не запрещает `values[0] = 9`. Фиксируется ссылка в переменной, а не все данные объекта. Поэтому static final у ссылочного поля само по себе не делает весь объект неизменяемым.

## 8. Разбираем main без перегруза

В привычном `public static void main(String[] args)`: `public` — доступность этой формы точки входа; `static` — запуск без заранее созданного экземпляра класса запуска; `void` — нет возвращаемого значения; `String[] args` — аргументы командной строки.

Современные Java поддерживают и другие формы точки входа. В этом курсе ты используешь показанную распространённую форму, но при чтении других примеров можешь встретить иные варианты.

## 9. Прогноз перед запуском

До первого `new` число созданий 0. После Анны и Бориса — 2. После `partner = anna` — по-прежнему 2. Неверная энергия приводит к отказу до увеличения счётчика — остаётся 2. Проверки `isValidEnergy(100)` и `isValidEnergy(101)` дают `true` и `false`.

Не просто назови ответ, а укажи строку, на которой меняется счётчик. Отличать «читаем значение» от «создаём объект» полезнее, чем запоминать результат примера.

## Программа для самостоятельного запуска

Каждый пример запускается отдельно. Классы `Student` в разных темах — последовательные учебные версии: не собирать их вместе в одном пакете. В терминале из его папки: `javac -encoding UTF-8 StaticDemo.java`, затем `java StaticDemo`. JDK 17 или новее.

```java
public class StaticDemo {
    public static void main(String[] args) {
        System.out.println(Student.getCreatedCount());
        Student anna = new Student("Анна", 70);
        Student boris = new Student("Борис");
        Student partner = anna;
        System.out.println(Student.getCreatedCount());
        System.out.println(partner == anna);
        System.out.println(boris.getEnergy());
        try {
            new Student("Ошибка", 101);
        } catch (IllegalArgumentException error) {
            System.out.println("Создание отклонено");
        }
        System.out.println(Student.getCreatedCount());
        System.out.println(Student.isValidEnergy(100));
        System.out.println(Student.isValidEnergy(101));
    }
}
class Student {
    public static final int MAX_ENERGY = 100;
    private static int createdCount;
    private String name;
    private int energy;
    Student(String name, int energy) {
        if (!isValidEnergy(energy)) {
            throw new IllegalArgumentException("Недопустимая энергия");
        }
        this.name = name;
        this.energy = energy;
        createdCount++;
    }
    Student(String name) {
        this(name, MAX_ENERGY);
    }
    public int getEnergy() {
        return energy;
    }
    public static int getCreatedCount() {
        return createdCount;
    }
    public static boolean isValidEnergy(int energy) {
        return energy >= 0 && energy <= MAX_ENERGY;
    }
}
```

Ожидаемый вывод:

```text
0
2
true
100
Создание отклонено
2
true
false
```

Перед запуском закрой готовый вывод и предскажи результат. Затем объясни каждое расхождение со своим прогнозом.
