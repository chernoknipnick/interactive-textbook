# ПР04. Классы, объекты и ссылки

Ориентир: 90 минут. Это первая из трёх работ закрепления блока ООП. Предыдущая работа — ПР03 «Собственные методы». Дальше: ПР05 — правила создания и изменения объектов, ПР06 — итоговая обработка массива объектов.

## Что должно получиться

Ты создашь собственный класс, два независимых экземпляра и ещё одну ссылку на один из них. Программа должна показывать, **какой объект изменился после действия**, а не только печатать случайные сообщения.

Понадобятся классы и объекты, методы, условия, ссылки и массивы. Повтори темы «Классы и объекты» и «Ссылки» по ссылкам вверху страницы. Полное решение своего варианта нужно написать самостоятельно; маленький пример ниже служит тренировкой.

## 1. Сначала попробуй готовый маленький пример

Создай отдельную папку `pr04-training`. Сохрани **RobotReferenceDemo.java**:

```java
public class RobotReferenceDemo {
    public static void main(String[] args) {
        Robot first = new Robot();
        first.name = "Альфа";
        first.energy = 80;

        Robot second = new Robot();
        second.name = "Бета";
        second.energy = 40;

        Robot alias = first;
        boolean done = alias.performAction();

        System.out.println(done);
        System.out.println(first.energy);
        System.out.println(second.energy);
        System.out.println(first == alias);
        System.out.println(first == second);
    }
}

class Robot {
    String name;
    int energy;

    boolean performAction() {
        if (energy < 10) {
            return false;
        }
        energy -= 10;
        return true;
    }
}
```

Запуск из папки файла:

```text
javac -encoding UTF-8 RobotReferenceDemo.java
java RobotReferenceDemo
```

Ожидаемый вывод:

```text
true
70
40
true
false
```

Почему так: `alias` и `first` ведут к одному Robot. Действие забрало у него 10 единиц энергии. У второго Robot осталось 40. Два вызова `new Robot()` создали два экземпляра; строка `Robot alias = first` только скопировала значение ссылки.

`performAction()` возвращает boolean: получилось ли выполнить действие. При нехватке ресурса он возвращает false и сохраняет прежнее состояние. Печать и само действие разделены: результат выводится из `main`.

Поля здесь пока доступны из соседнего класса того же пакета: у них нет `private`, но это не делает их публичными для всех пакетов. Такое упрощение позволит отдельно проследить ссылки. В ПР05 доступ к данным нужно будет организовать через конструкторы и методы.

## 2. Выбери сквозной вариант

Формула по номеру в журнале: **`((номер - 1) % 5) + 1`**. Например, 1 и 6 дают вариант 1, а 5 и 10 — вариант 5. Сохраняй этот вариант в ПР04, ПР05 и ПР06.

| Вариант | Класс | Поле ресурса | Максимум M | Расход C | Пополнение R | Низкий уровень L | Старт A | Старт B |
|---:|---|---|---:|---:|---:|---:|---:|---:|
| 1 | `Phone` | `battery` — заряд | 100 | 10 | 20 | 20 | 70 | 5 |
| 2 | `Player` | `stamina` — выносливость | 100 | 15 | 25 | 30 | 75 | 10 |
| 3 | `Printer` | `paper` — листы | 200 | 5 | 30 | 10 | 50 | 3 |
| 4 | `Car` | `fuel` — условные единицы топлива | 60 | 6 | 12 | 12 | 42 | 4 |
| 5 | `Lamp` | `charge` — заряд | 100 | 8 | 16 | 16 | 64 | 3 |

Смысл действия: Phone отправляет сообщение, Player выполняет приём, Printer печатает пакет страниц, Car выполняет учебную поездку, Lamp отрабатывает один интервал свечения. Это упрощённые модели с целочисленным ресурсом, а не расчёт физических характеристик реальных устройств.

В ПР04 понадобятся расход C и два начальных значения A/B. Остальные числа сохраняются для следующих работ. **Низкий уровень всегда означает строго меньше L**, а не меньше либо равно.

Имена собственного класса и методов вообще выбирает программист. В этих трёх работах используй имена из задания: так проще сравнивать результат с проверками. `performAction` — наше выбранное имя, а `class`, `new`, `return` — слова Java.

## 3. Собственный класс и два экземпляра

Создай другую папку `pr04-work`, файл **ObjectsWork.java**. В нём размести публичный класс запуска `ObjectsWork` и непубличный класс своего варианта. Класс `Robot` из тренировки в этот файл переносить не требуется.

Общая форма, которую нужно заменить конкретными именами:

```text
class ТипОбъекта {
    String name;
    int полеРесурса;

    boolean performAction() {
        проверить, достаточно ли ресурса;
        если недостаточно — вернуть false без изменения поля;
        иначе уменьшить поле на расход C и вернуть true;
    }
}
```

Это план, а не готовый Java-код. Например, для варианта 4 вместо `ТипОбъекта` нужен `Car`, вместо `полеРесурса` — `fuel`, а расход равен 6.

В `main`:

1. Создай `first` и `second` двумя отдельными выражениями `new`.
2. Присвой имена `"A"` и `"B"`.
3. Запиши в их поля ресурса значения из колонок «Старт A» и «Старт B».
4. Выведи имя и ресурс каждого до действий. Одинаковый набор полей не означает общие значения.

Пользовательский конструктор в этой работе не обязателен: если обычный класс вообще не объявляет конструкторов, компилятор предоставляет конструктор по умолчанию. Следующая работа изменит именно этот этап.

## 4. Проверь общую ссылку и независимый объект

Общий шаблон фрагмента внутри `main`:

```text
ТипОбъекта alias = first;
boolean firstResult = alias.performAction();
boolean secondResult = second.performAction();
```

Вызови действие **ровно один раз через alias и ровно один раз через second**. После этого выведи результаты и ресурс обоих объектов.

| Вариант | firstResult | first после действия через alias | secondResult | second после своей попытки |
|---:|---|---:|---|---:|
| 1 | true | 60 | false | 5 |
| 2 | true | 60 | false | 10 |
| 3 | true | 45 | false | 3 |
| 4 | true | 36 | false | 4 |
| 5 | true | 56 | false | 3 |

Если B ушёл в минус, проверь расположение проверки: она должна выполняться до вычитания. Если A не изменился, проверь, не создал ли ты в `alias` ещё один объект вместо копирования ссылки.

Выведи отдельно `first == alias` и `first == second`. Ожидаются true и false. Сравнение здесь отвечает на вопрос об одном и том же объекте, а не об одинаковых числах в полях.

## 5. Одинаковые данные ещё не означают один объект

Создай третий экземпляр `third`. Перепиши в него имя и текущее значение ресурса `first`. Это учебное копирование двух полей, а не универсальный способ копирования любых сложных объектов.

Проверь `first == third`: получится false, хотя значения двух полей совпадают. В этой части существует уже три экземпляра твоего класса.

Затем присвой `alias = null`. Прочитай ресурс через `first`: он сохранится. Присваивание null одной переменной не стирает объект, доступный через другую ссылку. Не вызывай `alias.performAction()` после этого присваивания: у alias больше нет получателя для экземплярного вызова.

## 6. Массив ссылок — отдельный опыт

Выполни его после предыдущих действий. Здесь снова используются `first` и `second`; новые экземпляры твоего класса не создаются.

```text
ТипОбъекта[] group = new ТипОбъекта[3];
group[0] = first;
group[1] = second;
group[2] = first;
```

Замени `ТипОбъекта` своим классом. Сразу после `new ТипОбъекта[3]` все три элемента равны null. После присваиваний первый и третий элементы ведут к одному объекту. Проверь `group.length` и `group[0] == group[2]`: ожидаются 3 и true.

Нарисуй три ячейки отдельно от двух объектов, на которые они ссылаются. Третий объект `third` из предыдущего раздела по-прежнему может существовать, но в этом массиве ссылки на него нет.

Ответь до запуска: если выполнить `group[2].performAction()`, изменится ли значение, читаемое через `group[0]`? Да: получатель у двух обращений общий. Этот дополнительный вызов делай уже после проверки таблицы раздела 4, чтобы не изменить её исходный сценарий.
