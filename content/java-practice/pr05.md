# ПР05. Конструкторы, инкапсуляция и static

Ориентир: 90 минут. Продолжаем свой вариант из ПР04. Теперь класс должен получать допустимое состояние при создании и сохранять его после разрешённых действий.

## Что должно получиться

В результате будут закрытые личные поля, два конструктора, действия с проверками, методы чтения и общий счётчик созданий. Методы класса возвращают данные, а `main` показывает результаты человеку.

Для этой работы нужны конструкторы, `this`, методы, условия и `static`. Первое знакомство с `throw new IllegalArgumentException(...)` есть в лекциях о конструкторах и заключении ООП. Проверки неверных параметров ниже можно запускать отдельными опытами.

## 1. Подготовь отдельную версию проекта

Сохрани результат ПР04. Создай папку `pr05-work` и файл **ConstructionWork.java**: публичный класс запуска `ConstructionWork`, рядом непубличный класс выбранного варианта.

Не складывай реализации одного и того же Phone, Player или другого класса из ПР04 и ПР05 в один пакет. Для этих отдельных учебных программ достаточно отдельных папок и запуска нужного файла из своей папки.

## 2. Числа своего варианта

Номер остаётся прежним: `((номер - 1) % 5) + 1`.

| Вариант | Класс | Личное поле ресурса | MAX_LEVEL | ACTION_COST | REFILL_AMOUNT | LOW_THRESHOLD | Старт A |
|---:|---|---|---:|---:|---:|---:|---:|
| 1 | Phone | battery | 100 | 10 | 20 | 20 | 70 |
| 2 | Player | stamina | 100 | 15 | 25 | 30 | 75 |
| 3 | Printer | paper | 200 | 5 | 30 | 10 | 50 |
| 4 | Car | fuel | 60 | 6 | 12 | 12 | 42 |
| 5 | Lamp | charge | 100 | 8 | 16 | 16 | 64 |

MAX_LEVEL — верхняя граница; ACTION_COST — расход одного действия; REFILL_AMOUNT — размер одного пополнения; LOW_THRESHOLD — граница низкого уровня. Состояние считается низким **при уровне строго меньше LOW_THRESHOLD**.

## 3. Сначала изучи маленький образец

Это отдельный тренировочный пример: **RobotConstructorDemo.java** в папке `pr05-training`. Он показывает связь параметров, полей, делегирования конструкторов и счётчика; собственные действия своего класса допиши самостоятельно.

```java
public class RobotConstructorDemo {
    public static void main(String[] args) {
        Robot first = new Robot("Альфа", 70);
        Robot second = new Robot("Бета");
        Robot alias = first;
        System.out.println(alias.getEnergy());
        System.out.println(second.getEnergy());
        System.out.println(Robot.getCreatedCount());
    }
}

class Robot {
    private String name;
    private int energy;
    private static int createdCount;

    Robot(String name, int energy) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("Нужно непустое имя");
        }
        if (energy < 0 || energy > 100) {
            throw new IllegalArgumentException("Энергия вне диапазона");
        }
        this.name = name;
        this.energy = energy;
        createdCount++;
    }

    Robot(String name) {
        this(name, 100);
    }

    public int getEnergy() {
        return energy;
    }

    public static int getCreatedCount() {
        return createdCount;
    }
}
```

Запусти `javac -encoding UTF-8 RobotConstructorDemo.java`, затем `java RobotConstructorDemo`. Ожидаемый вывод: 70, 100 и 2, каждое значение с новой строки.

`name.isBlank()` проверяет пустую строку или строку только из пробельных символов. `||` сначала проверяет `name == null`: если это true, правый вызов вообще не вычисляется. Так метод не вызывается через null. В используемой для курса Java 17/21 этот библиотечный метод доступен.

`this.name = name` сохраняет значение параметра в поле текущего объекта. `this(name, 100)` — другая запись: она вызывает второй конструктор того же класса для инициализации того же экземпляра. В этом образце делегирующий конструктор не увеличивает счётчик повторно.

## 4. Объяви данные своего класса

Общая форма, не готовый файл:

```text
class ТипОбъекта {
    public static final int MAX_LEVEL = число_варианта;
    public static final int ACTION_COST = число_варианта;
    public static final int REFILL_AMOUNT = число_варианта;
    public static final int LOW_THRESHOLD = число_варианта;

    private String name;
    private int полеРесурса;
    private static int createdCount;
}
```

`static` относит выбранные поля к классу; `final` запрещает повторное присваивание после их допустимой инициализации. Здесь числа являются постоянными правилами варианта. Публичными остаются эти константы и предусмотренные методы; изменяемые личные данные и счётчик закрыты.

Перенеси числа из своей строки таблицы. Используй их имена в методах, чтобы правила не приходилось угадывать по повторяющимся числам.

## 5. Реализуй два конструктора

| Объявление в общем виде | Обязательное поведение |
|---|---|
| `ТипОбъекта(String name, int level)` | Проверить имя и уровень, записать их в поля, увеличить счётчик один раз |
| `ТипОбъекта(String name)` | Вызвать основной конструктор с MAX_LEVEL |

Это образцы сигнатур с заменяемым именем класса. Имя конструктора должно совпадать с выбранным классом. Тип результата и `void` перед ним не пишутся.

Правила:

1. Имя не равно null и не состоит только из пробельных символов. Проверку можно построить по образцу Robot.
2. Уровень от 0 до MAX_LEVEL включительно.
3. При неверном параметре выбрасывается `IllegalArgumentException` с понятным сообщением.
4. Счётчик увеличивается после проверок, в основном конструкторе. Копирование ссылки и вызовы методов его не увеличивают.
5. В конструкторе с одним параметром используй `this(name, MAX_LEVEL)` первой инструкцией, как в учебном образце.

Объект нельзя сначала создать с произвольными значениями, а потом «дозаполнить когда-нибудь». После нормального завершения конструктора нужные данные уже должны быть установлены.

## 6. Контракт методов

Контракт — договорённость о входных данных, результате и изменении состояния. Реализуй следующие методы с точными именами:

| Метод | Что возвращает | Что изменяет |
|---|---|---|
| `public String getName()` | Сохранённое имя | Ничего |
| `public int getLevel()` | Текущее значение своего поля ресурса | Ничего |
| `public boolean performAction()` | true при успехе, false при нехватке | При успехе вычитает ACTION_COST; иначе сохраняет уровень |
| `public void refill()` | Значения нет | Прибавляет REFILL_AMOUNT, ограничивая результат MAX_LEVEL |
| `public boolean isLow()` | `getLevel() < LOW_THRESHOLD` по смыслу | Ничего |
| `public static boolean isValidLevel(int level)` | Допустим ли уровень от 0 до MAX_LEVEL | Ничего; объекты не создаёт |
| `public static int getCreatedCount()` | Число нормальных созданий своего класса в этом запуске | Ничего |

Используй isValidLevel в основном конструкторе. Тип int у параметра isValidLevel и тип boolean результата отвечают на разные вопросы: что получаем и что отдаём.

Схема действия performAction:

```text
если ресурс меньше ACTION_COST:
    вернуть false, не меняя поле
иначе:
    вычесть ACTION_COST
    вернуть true
```

Схема refill:

```text
новыйУровень = прежнийУровень + REFILL_AMOUNT
если новыйУровень больше MAX_LEVEL:
    сохранить MAX_LEVEL
иначе:
    сохранить новыйУровень
```

Это алгоритмы, не готовый Java-код. В небольших числовых диапазонах наших вариантов сложение помещается в int. Обе схемы работают с полем конкретного экземпляра; этому полю не нужен static.

Методы своего класса в этой работе не печатают результаты. Печать выполняет main: например, `System.out.println(first.getLevel());`. Сеттер, разрешающий прямую произвольную замену уровня, для задачи не требуется.

## 8. Проверь границы, а не только удобный пример

Для каждой строки возьми новый объект с указанным начальным уровнем. Буквы C, R, L и M означают расход, пополнение, границу низкого уровня и максимум своего варианта.

| Проверка | Ожидаемый результат |
|---|---|
| performAction при 0 | false, остаётся 0 |
| performAction при C − 1 | false, уровень не меняется |
| performAction при C | true, остаётся 0 |
| refill при 0 | R |
| refill при M − 1 | M, превышения нет |
| refill при M | По-прежнему M |
| isLow при L − 1 | true |
| isLow при L | false |
| isValidLevel при −1 и M + 1 | false |
| isValidLevel при 0 и M | true |

Затем отдельными запусками попробуй конструктор с уровнем −1, с M + 1, с null вместо имени и с `"   "`. Ожидается исключение. Необработанное исключение завершит текущий сценарий, поэтому четыре неверных создания подряд не проверятся сами собой: меняй один входной пример за запуск.

Проверка isValidLevel не выбрасывает исключение и не создаёт объект. А конструктор использует её результат, чтобы решить, можно ли нормально завершить создание.
