# ПР06. Итоговая система объектов

Ориентир: две пары по 90 минут. Это завершающая работа начального блока: свой класс из ПР05 соединяется с массивом, циклами, методами и проверяемыми результатами.

## Результат работы

Создай консольную мини-систему учёта объектов своего варианта. Она показывает состояние группы, вычисляет статистику, выполняет по одному действию и пополняет ресурс там, где он низкий. Итог должен объясняться по шагам и воспроизводиться на фиксированных данных.

Обязательная часть опирается на уже изученную базу: классы, ссылки, конструкторы, инкапсуляцию, static, массивы, условия и методы. Отдельные разновидности объектов и общий контракт через наследование можно разбирать в следующем блоке.

## 1. Подготовка

Создай папку `pr06-work`, файл **OopBlockWork.java**. Публичный класс запуска — `OopBlockWork`. Перенеси в него рядом непубличный класс своего варианта из ПР05 и проверь его методы.

Тренировочные классы и старые версии Phone/Player/Printer/Car/Lamp оставь в их отдельных папках. В одной учебной программе не должно оказаться двух объявлений класса с одинаковым именем в одном пакете.

Вариант сохраняется: `((номер - 1) % 5) + 1`.

| Вариант | Система | Класс | Поле ресурса | M — максимум | C — расход | R — пополнение | L — низкий уровень |
|---:|---|---|---|---:|---:|---:|---:|
| 1 | Парк учебных телефонов | Phone | battery | 100 | 10 | 20 | 20 |
| 2 | Команда игроков | Player | stamina | 100 | 15 | 25 | 30 |
| 3 | Очередь принтеров | Printer | paper | 200 | 5 | 30 | 10 |
| 4 | Учебный автопарк | Car | fuel | 60 | 6 | 12 | 12 |
| 5 | Группа автономных ламп | Lamp | charge | 100 | 8 | 16 | 16 |

Уровень считается низким строго при значении меньше L. Состояние каждого объекта остаётся от 0 до M включительно.

## 2. Короткая тренировка: метод читает объекты через ссылки

Отдельный пример **CounterArrayDemo.java** в папке `pr06-training`:

```java
public class CounterArrayDemo {
    public static void main(String[] args) {
        Counter[] counters = {new Counter(2), new Counter(5)};
        System.out.println(sumValues(counters));
        counters[0].reduce();
        System.out.println(sumValues(counters));
    }

    static int sumValues(Counter[] values) {
        int total = 0;
        for (Counter item : values) {
            total += item.getValue();
        }
        return total;
    }
}

class Counter {
    private int value;

    Counter(int value) {
        this.value = value;
    }

    public int getValue() {
        return value;
    }

    public void reduce() {
        if (value > 0) {
            value--;
        }
    }
}
```

Запусти `javac -encoding UTF-8 CounterArrayDemo.java`, затем `java CounterArrayDemo`. Вывод — 7, затем 6. Первый Counter изменился с 2 на 1; второй остался 5. Метод суммы создал локальный total, прочитал состояния существующих объектов и вернул число. Новых Counter при подсчёте суммы он не создавал.

Это только тренировка суммирования. Требования к полноценной модели и её проверкам заданы твоим классом из ПР05.

## 3. Создай исходную группу

В основной программе должен быть массив из **четырёх разных экземпляров** с именами A, B, C, D. Все создания выполняются один раз в main. Первый этап нужен для точной проверки алгоритмов: фиксированные данные важнее случайного заполнения.

| Имя | Начальный уровень | Назначение проверки |
|---|---:|---|
| A | 0 | Полностью пустой ресурс |
| B | ACTION_COST − 1 | Не хватает одной единицы до действия |
| C | ACTION_COST | Ровно хватает на одно действие |
| D | MAX_LEVEL | Верхняя граница |

Общая форма создания массива внутри main; это шаблон с заменяемым типом:

```text
ТипОбъекта[] items = {
    new ТипОбъекта("A", 0),
    new ТипОбъекта("B", ТипОбъекта.ACTION_COST - 1),
    new ТипОбъекта("C", ТипОбъекта.ACTION_COST),
    new ТипОбъекта("D", ТипОбъекта.MAX_LEVEL)
};
```

Здесь создаются массив и четыре экземпляра твоего класса. Его собственный createdCount должен показывать 4. Он не считает массив, строки и локальные переменные. Ссылки на четыре объекта различны; в исходном массиве нет null и повторных ссылок.

## 4. Раздели обработку на методы

Вычисляющие и управляющие методы объяви как static в `OopBlockWork`, снаружи main. Каждый получает массив явно. Личные действия остаются обычными методами объектов своего класса.

В таблице `ТипОбъекта` — выбранный класс, а `values` — выбранное имя параметра. Вместо шаблона нужно написать настоящее объявление.

| Общая форма метода | Требование |
|---|---|
| `static void printAll(ТипОбъекта[] values)` | Напечатать имя и текущий уровень каждого; значения не менять |
| `static int sumLevel(ТипОбъекта[] values)` | Вернуть сумму уровней, без печати и создания новых объектов |
| `static double averageLevel(ТипОбъекта[] values)` | Вернуть средний уровень с дробной частью |
| `static int countLow(ТипОбъекта[] values)` | Посчитать элементы, у которых isLow() возвращает true |
| `static ТипОбъекта findMax(ТипОбъекта[] values)` | Вернуть ссылку на существующий объект с максимальным уровнем; при равенстве выбрать первый |
| `static int performAll(ТипОбъекта[] values)` | Вызвать performAction() ровно один раз для каждого и вернуть количество успешных действий |
| `static void refillLow(ТипОбъекта[] values)` | При обходе один раз проверить каждый объект и один раз вызвать refill(), только если его уровень низкий |

Контракт этих методов в обязательной части: массив не равен null, непустой, каждый элемент содержит ссылку на объект. Тестовый массив раздела 3 удовлетворяет этому условию.

### Как рассуждать о sumLevel и averageLevel

Накопитель начинается с 0. Цикл читает `item.getLevel()` у каждого получателя и прибавляет число. Итоговый return ставится после обхода.

Для среднего сначала получи сумму, затем выполни `(double) сумма / длина`. Если вычислить целочисленное деление до приведения, дробная часть уже потеряется.

### Как рассуждать о findMax

Первый элемент — начальный кандидат. При просмотре остальных меняй ссылку на кандидата только при **строго большем** уровне. Тогда при равенстве останется первый встретившийся объект.

Не создавай новый объект ради результата поиска. Метод должен вернуть одну из ссылок, уже находящихся в массиве. Иначе потеряется идентичность, а счётчик созданий изменится.

### Как рассуждать о performAll и refillLow

performAction возвращает результат попытки. Увеличивай счётчик успехов только при true, а не при каждом посещённом элементе.

refillLow делает **один проход и не более одного пополнения на объект**. Если после одного пополнения уровень всё ещё низкий, он таким и остаётся до следующего отдельно заданного прохода. Здесь не нужен цикл «пополнять до нормального уровня».

## 5. Выполни три этапа в точном порядке

1. **До действий:** выведи группу, сумму, среднее, количество низких уровней, имя максимального и createdCount.
2. **После действий:** один раз вызови performAll, выведи число успехов и снова состояние со статистикой.
3. **После пополнения:** один раз вызови refillLow и снова выведи состояние со статистикой.

Методы статистики при повторном вызове должны пересчитывать текущее состояние. Переменная с однажды вычисленной суммой сама по себе не изменится после действий объектов.

## 6. Ожидаемые результаты своего варианта

В скобках перечислены уровни **A, B, C, D в этом порядке**. Среднее ниже относится к четырём элементам. Два действия должны оказаться успешными во всех вариантах, максимальным на каждом из трёх этапов будет D.

| Вариант | Низких до действий | Низких после действий | Низких после пополнения | Создано объектов своего класса |

Во втором варианте A и C после пополнения имеют 25, что всё ещё меньше 30. Поэтому ответ 2 верен. Если программа получила 0, возможно, ты повторял пополнение до достижения границы вместо одного вызова.

Формат подписей можешь выбрать сам, но каждое число должно быть понятно: этап, имя, уровень, сумма, среднее, количество низких, максимум и счётчик. Дробная точка в примерах соответствует обычному выводу double через println.

## 7. Проверь идентичность и отсутствие лишних созданий

До действий сохрани `alias = items[3]` с типом своего класса. Убедись, что `alias == items[3]` даёт true, а createdCount остаётся 4.

Вызови findMax на каждом из трёх этапов и проверь, что результат `== items[3]`. Создание копии с таким же именем не проходит эту проверку. Читающие методы sumLevel, averageLevel, countLow и findMax не должны менять уровни и счётчик.

Отдельная диагностика после контрольного сценария: создай два разных объекта с одинаковым уровнем, помести их в новый массив и проверь, что findMax вернул ссылку на первый. Эти дополнительные создания закономерно увеличат createdCount. Таблицы раздела 6 проверяются раньше, на исходных четырёх объектах.

## 8. Дополнительные задания по желанию

После обязательных проверок можно добавить поиск по имени, вывод только низких уровней или ввод пользовательских значений. Новое действие должно сохранять правила класса и не ломать воспроизводимый контрольный сценарий.

Ещё один опыт со ссылками: помести один объект в массив дважды и вызови performAll. Действие будет вызвано для каждой позиции, поэтому общий объект может измениться дважды. Различай число элементов массива и число разных экземпляров. Основной вариант работы использует четыре разных экземпляра.

## Когда начальный блок можно считать закреплённым

Работа готова, если выполняются все условия:

- Класс создаёт допустимый объект через конструктор; личные поля закрыты.
- performAction, refill и isLow соблюдают контракт своего варианта.
- Личный ресурс не объявлен static, общий счётчик не размножен по объектам.
- Все семь методов обработки имеют понятную задачу и получают массив явно.
- Значения трёх этапов совпадают с таблицами, включая дробное среднее и строгую границу L.
- findMax возвращает существующий объект и выбирает первый при равенстве.
- Программа повторно запускается с теми же проверяемыми результатами.
- Ты можешь объяснить выбранный вызов от параметра до изменения поля и возвращаемого результата.
