# Интерактивный учебник

Авторские лекции по базам данных, настройка окружения, SQL-песочница на SQLite, квиз и анимация пути запроса.

## Запуск локально

Из корня репозитория:

```sh
python scripts/build.py
python -m http.server 8765 --directory build
```

Открыть http://localhost:8765. Нужен Python 3.10 или новее; для подготовки сайта внешние пакеты не требуются.

`dist/` — отслеживаемые исходные статические страницы и ресурсы. `build/` — результат подготовки, исключённый из Git. Скрипт копирует `dist/`, добавляет общую шапку, темы и иконки, убирает внешние шрифты и создаёт `.nojekyll`. Повторный запуск заменяет только `build/` и не меняет исходные файлы. Историческая команда `python scripts/site_icons.py` теперь тоже готовит `build/`.

После изменения Markdown сначала запустите соответствующий генератор материалов, затем `python scripts/build.py`. Генераторы сохраняют страницы в `dist/`, а общая оболочка добавляется только при подготовке `build/`. Не редактируйте готовую папку `build/`. Для проверки чистоты сборки выполните `git status --short` до и после: набор изменений должен остаться прежним.

## Публикация

В Settings → Pages выбрать Source → GitHub Actions. Каждый push в `main` запускает `python scripts/build.py` и публикует папку `build` через `.github/workflows/pages.yml`. Для предпросмотра используется тот же шаг подготовки. Дополнительные секреты для сборки не нужны.

## Файлы

- `dist/index.html`, `style.css`, `app.js` — главная страница и навигация.
- `dist/lectures/course.html` — пять авторских лекций с исходными цветами и схемами.
- `dist/lectures/setup.html` — настройка окружения.
- `dist/practice.html` — SQL-песочница, квиз и тренажёр команд.
- `dist/assets/` — SQL.js и WebAssembly-движок SQLite.

Все ссылки относительные: сайт поддерживает размещение в подпапке GitHub Pages.

Прогресс хранится в localStorage конкретного браузера. SQL-база учебная и хранится в памяти вкладки; изменения базы исчезают при перезагрузке. Тренажёр команд — симуляция, которая не устанавливает программы. 

SQL.js: https://github.com/sql-js/sql.js (MIT).

## Лекции Java из Obsidian

В `content/java/` сохранены студенческие версии актуальных материалов: 14 конспектов и 14 полных лекций. Сценарии «Лекция преподавателю» и архивная папка «Лекции неактуально» не импортируются.

Для повторной генерации HTML из сохранённого Markdown (Python, пакеты Markdown и Pygments):

```sh
python scripts/import-java.py
```

Чтобы обновить копии из Obsidian, передать путь к папке «Лекции джава/Лекции новые/Java» аргументом:

```sh
python scripts/import-java.py "путь/к/папке/Java"
```

Сгенерированные страницы лежат в `dist/java/`, перечень тем — в `dist/java-lessons.js`. Синхронизация с Obsidian выполняется вручную запуском импорта; автопубликация GitHub Pages происходит после push в `main`.

Онлайн-лекции адресованы студентам: текст объясняет понятия, обращается к читателю и предлагает самостоятельные задания. Полные версии в `content/java/*-lecture.md` редактируются как отдельные студенческие материалы. Сценарии преподавателю не служат их автоматическим источником. Импортёр отклоняет явные преподавательские метки и указания вроде «Попросите» и «На доске написать», а не удаляет их молча. При дополнении лекции сохраняйте подробные разборы кода и анимации.

## Практические и лабораторные Java

В `content/java-practice/` сохранены семь актуальных студенческих работ: ЛР01, ЛР02, ПР02–ПР06. Страницы с вариантами заданий опубликованы в `dist/java/work-*.html`, список — `dist/java-practices.js`. Решения и методички преподавателя, старые работы и пустые заготовки не импортируются.

Повторная загрузка из папки «Лабораторные работы» Obsidian:

```sh
python scripts/import-java.py --practice-source "путь/к/Лабораторные работы"
```

Команда без аргументов пересобирает лекции и практику из сохранённых Markdown-копий.

## Наглядные примеры Java

У всех 14 тем есть пошаговая модель. Для обзора языков, введения, типов, поразрядных операций, циклов и методов используется `course-traces.js/css`: код перед состоянием, шаг назад/вперёд, проигрывание, пауза и сброс. Сценарии хранятся в `content/java-visuals/*.html`; это заранее подготовленные трассировки, а не интерпретатор Java. Дополнения к лекциям содержат общую форму конструкций с пояснением заменяемых имён, полную программу, ожидаемый вывод, разбор состояния, ошибки и самостоятельную проверку.

В темах первой программы, условий и массивов добавлены пошаговые учебные модели. Разметка хранится в `content/java-visuals/`, поведение и стили — `dist/java/visuals.js` и `visuals.css`. Импортёр вставляет схемы в соответствующие лекции при пересборке. Это модели для объяснения, не исполнитель произвольного Java-кода.

Темы ссылок, классов и объектов, конструкторов и static содержат отдельные анимированные модели (`oop-visuals.js` и `oop-visuals.css`): шаг вперёд/назад, проигрывание, пауза и сброс. Автопроигрывание останавливается в конце и при уходе со страницы. Системная настройка уменьшенного движения учитывается. Код и объяснения доступны текстом рядом со схемой.

Десять цветных иллюстраций хранятся в `content/java-assets/` и копируются импортёром в `dist/java/images/`. Obsidian-вложения `![[Схемы ООП/имя.png]]` преобразуются в обычные изображения; отсутствующее вложение прерывает сборку. Учебные версии Student в разных темах запускаются отдельно.

Перед каждой инфографикой выводится объясняемый фрагмент Java и его контекст из `content/java-diagram-code.json`. Схема массива студентов представлена адаптивной HTML-разметкой: три ячейки, два существующих объекта и null в третьей ячейке. Это отдельный пример, не подмена основного массива длины два. Для растровых схем доступно открытие полного изображения.

`scripts/lesson_presentation.py` формирует семантическую подсветку и общую легенду: типы/классы, объекты/ссылки, данные, методы и конструкции языка. Данные объединяют поля, параметры и локальные переменные: их точную роль определяет контекст. Строковые значения не размечаются как имена. Стили — `lesson-semantics.css`; анимированные строки кода используют ту же палитру через `lesson-semantics.js`.

## Заключение по основам ООП

Тема `oop-summary` завершает начальный блок после static: повторение модели объектов и ссылок, инкапсуляция, вводная карта абстракции, наследования и полиморфизма. Два самостоятельных примера запускаются в отдельных папках из-за разных учебных реализаций Phone. Две шестишаговые модели используют `course-traces.js`, две адаптивные схемы — `oop-summary.css`. Новые языковые механизмы разобраны рядом с полными программами; это введение к дальнейшим отдельным темам, а не заявление об исчерпывающем изучении ООП.

## Закрепление начального блока ООП

ПР04–ПР06 образуют последовательность: классы и ссылки; конструкторы, инкапсуляция и static; итоговая система с массивом объектов. Пять сквозных вариантов сохраняют предметную область и числовые правила во всех трёх работах. Обязательная часть закрепляет базу; наследование и интерфейсы остаются темами дальнейшего расширения. Задания содержат фиксированные проверки, границы и условия готовности. Три пошаговые модели готовых тренировочных примеров хранятся в `content/java-practice-visuals/` и используют существующий `course-traces.js`. Публичная папка content содержит студенческие задания; преподавательские материалы и эталонные решения хранятся отдельно локально.

## Личный кабинет и группы

Страница dist/account использует Supabase Auth и PostgreSQL. Студенты ведут профиль и вступают в группы по коду. Преподаватель создаёт свои группы, обновляет коды и видит участников. Настройка описана в supabase/README.md, схема и тесты доступа находятся в той же папке.


## Поиск, ссылки и проверка артефакта

Сборка автоматически добавляет описания и Open Graph, исправляет уровни заголовков, создаёт `404.html`, `sitemap.xml`, `robots.txt` и полнотекстовый `build/search-index.json`. Поисковый индекс не записывается в `dist/`: он пересчитывается по фактически подготовленным материалам и проверяется на лимит 150 000 байт. Общий словарь и списки документов хранятся компактно, без потери слов из индексируемого текста. Меню, скрипты, стили и повторный конспект исключены.

Хеши маршрутов (`#java-languages`) не отправляются серверу: мессенджер видит описание главной. Для карточки конкретной Java/ИТ-лекции отправляйте прямой HTML-адрес. Кнопка «Ссылка» в содержании Java копирует прямой адрес с разделом. В SQL пока пять лекций находятся в одном документе и имеют общую карточку ссылки; разделение документов относится к P2.

Читалка понимает `#java-languages/lecture-_6`. Явный раздел имеет приоритет над сохранённой позицией; сохранение локальное для браузера, без передачи преподавателю. «Открыть отдельно» сохраняет текущий раздел в прямой ссылке.

Проверка без браузерных зависимостей:

```sh
python scripts/build.py
python -m unittest discover -s tests -v
```

Эти же проверки выполняются в GitHub Actions перед публикацией. Для оценки взаимодействий используется Chrome: поиск (в том числе слова DEX, транзакция, инкапсуляция), клавиатура, возврат к позиции, обычный и уменьшенный режим движения.
